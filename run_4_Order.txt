⭐ FUNKCIONÁLIS SPECIFIKÁCIÓ (v1.2 – kód‑szinkronizált, pontosított)

Gyártási rendeléskezelő és anyagigény‑képző rendszer
(NeedCalculator + Order + Worksheet + WorkOrder jövőmodell)

------------------------------------------------------------------------

1. Rendszer célja

A rendszer feladata:

-   ügyfél megrendeléseinek kezelése (Order),
-   megrendelésen belüli tételek kezelése (OrderLine / OrderItem),
-   tételenkénti anyagigény számítása (NeedCalculator → ItemNeed),
-   egy megrendelés teljes anyagigényének előállítása (OrderNeedBuilder
    → OrderNeed),
-   egy megrendelésből gyártási lista (vágás + kitting) előállítása
    (WorksheetBuilder → WorksheetNeed),
-   több megrendelésből munkalap összeállítása (WorkOrder – jövőmodell),
-   munkalaphoz tartozó aggregált anyagigény előállítása (WorkOrderNeed
    – jövőmodell),
-   a gyártás számára vágási és kitting listák generálása
    (CutAggregator, KitAggregator).

A rendszernek támogatnia kell:

-   több order → egy munkalap (WorkOrder),
-   egy orderen belül több tétel (OrderItem / OrderLine),
-   qty szorzást (Order szinten, nem a NeedCalculator‑ban),
-   aggregálást (azonos anyagok összevonása vágásnál és kittingnél),
-   auditálhatóságot (OrderNeed, WorksheetNeed, WorkOrderNeed
    struktúrák),
-   visszakereshetőséget (externalId, ownerName, productId, stb.).

------------------------------------------------------------------------

2. Fő entitások és rétegek

A rendszer három logikai rétegben működik:

1.  Order szint – ügyfélmegrendelések és tételek (Order, OrderItem /
    OrderLine)
2.  Need szint – anyagigény számítása és reprezentációja (ItemNeed,
    OrderNeed)
3.  Gyártási lista / WorkOrder szint – aggregált gyártási igények
    (WorksheetNeed, később WorkOrderNeed)

Mindhárom réteg külön felelősséget visz, és együtt alkotják a gyártási
pipeline‑t.

------------------------------------------------------------------------

⭐ 2.1. ORDER SZINT

2.1.1. Order – ügyfélmegrendelés (jövőbeli domain modell)

Cél: egy ügyfél által leadott megrendelés reprezentációja.

Attribútumok (tervezett orders/model/order.h):

-   id: QUuid
-   orderNumber: QString (pl. “2026‑0001”)
-   customerName: QString
-   orderDate: QDate
-   lines: QVector (vagy QVector – lásd alább)

Viselkedés:

-   egy Order több OrderLine / OrderItem elemet tartalmaz,
-   egy OrderLine egy terméket és annak paramétereit írja le,
-   az Order szint nem számol anyagigényt, csak adatot hordoz.

Fontos pontosítás:
A calculation/service/order_need_builder.h fájlban található
Order/OrderItem nem perzisztens domain, hanem számítási pipeline input
DTO.
A perzisztens Order domain a orders/model/order.h lesz.

------------------------------------------------------------------------

2.1.2. OrderLine – megrendelési tétel (NeedCalculator input)

A NeedCalculator jelenlegi OrderLine típusa:

    struct OrderLine {
        QUuid productId;
        int width_mm = 0;
        int height_mm = 0;
        QString handlerSide;
        QString externalId;
        QString ownerName;
        QString colorName;
    };

Attribútumok:

-   productId: QUuid – terméktípus (ProductMaster.id)
-   width_mm, height_mm: méretek mm‑ben
-   handlerSide: “L” / “R” / üres
-   externalId: külső azonosító (pl. ügyfél tételszám: “1243”)
-   ownerName: megrendelő neve (pl. “Teszt Elek”)
-   colorName: szín megnevezése (pl. “Fehér”)

Viselkedés:

-   egy OrderLine egy darab fizikai termék paramétereit írja le,
-   a NeedCalculator mindig 1 db ItemNeed‑et számol,
-   a darabszám (qty) nem része ennek a struktúrának.

------------------------------------------------------------------------

2.1.3. OrderItem – Order + qty + mód (jelenlegi builder input)

A calculation/service/order_need_builder.h jelenlegi modellje:

    struct OrderItem {
        QUuid orderItemId;
        OrderLine line;
        int order_qty = 1;
        QString modeName;
    };

Attribútumok:

-   orderItemId – tétel azonosító
-   line – OrderLine - a termék paraméterei
-   order_qty – hány darab készül ebből a tételből
-   modeName – számítási mód neve (pl. “Manufacturing”)

Viselkedés:

-   egy OrderItem egy logikai rendelési sor (OrderLine + qty + mode),
-   a qty szorzás az OrderNeedBuilder‑ben történik.

------------------------------------------------------------------------

⭐ 2.2. NEED SZINT

2.2.1. NeedCalculation / NeedCalculationDetail

Már létező domain:

-   NeedCalculation – termékhez tartozó számítási mód
-   NeedCalculationDetail – formula egy anyagra (Cutting / Kitting)

Ezeket használja a NeedCalculator a DSL futtatásához.

------------------------------------------------------------------------

2.2.2. ItemNeed – egy darab termék anyagigénye

Jelenlegi definíció (need_calculator.h):

    struct ItemNeed {
        QVector<RawCut> cutItems;
        QVector<RawKit> kitItems;
    };

Attribútumok:

-   cutItems: QVector – vágási tételek (nem aggregált),
-   kitItems: QVector – kitting tételek (nem aggregált).

Viselkedés:

-   egy ItemNeed egy darab fizikai termék anyagigényét írja le,
-   nem aggregált, nem szorzott,
-   a NeedCalculator::calculate(line, modeName) mindig 1 db ItemNeed‑et
    ad vissza.

A korábbi specifikációban szereplő orderLineId itt nincs benne – a
kapcsolatot az OrderItemNeed szint hordozza.

------------------------------------------------------------------------

2.2.3. OrderItemNeed – egy rendelési tétel összes példánya

Jelenlegi definíció (need_calculator.h):

    struct OrderItemNeed {
        QUuid orderItemId;
        OrderLine line;
        QVector<ItemNeed> itemNeeds;
    };

Attribútumok:

-   orderItemId: QUuid – hivatkozás az OrderItem‑re,
-   line: OrderLine – a tétel metaadatai (productId, méretek, owner,
    stb.),
-   itemNeeds: QVector – minden fizikai példány külön ItemNeed‑ként.

Viselkedés:

-   az OrderNeedBuilder:
    -   meghívja NeedCalculator::calculate(line, modeName)‑et,
    -   az eredményt order_qty‑szer ismétli,
    -   minden példányt külön ItemNeed elemként tárol az itemNeeds
        vektorban.
-   NeedCalculator → 1 db ItemNeed,
-   OrderNeedBuilder → ismétli order_qty alkalommal,
-   az itemNeeds.size() adja a darabszámot.

------------------------------------------------------------------------

2.2.4. OrderNeed – egy teljes Order anyagigénye

    struct OrderNeed {
        QUuid orderId;
        QVector<OrderItemNeed> orderItemNeeds;
    };

------------------------------------------------------------------------

⭐ 2.3. GYÁRTÁSI LISTA / WORKSHEET / WORKORDER SZINT

2.3.1. WorksheetNeed – aggregált vágási és kitting lista

Jelenlegi definíció (calculation/service/worksheet_builder.h):

    struct WorksheetNeed {
        QUuid worksheetId;
        QVector<CutAggregatedItem> cuts;
        QVector<KitAggregatedItem> kits;
    };

Attribútumok:

-   worksheetId: QUuid – jelenleg az OrderNeed.orderId‑vel azonosítva,
-   cuts: QVector – aggregált vágási lista,
-   kits: QVector – aggregált kitting lista.

Viselkedés:

-   a WorksheetBuilder::fromOrderNeed(orderNeed):
    -   végigmegy az összes OrderItemNeed‑en,
    -   minden ItemNeed‑ből Piece és KitItem listát épít,
    -   majd CutAggregator::aggregate és KitAggregator::aggregate
        segítségével aggregál.

Ez a struktúra gyakorlatilag a WorkOrderNeed egy Orderre szűkített
változata. Később több OrderNeed összefűzésével épülhet a WorkOrderNeed.

Pontosítás – aggregálási kulcsok (kód szerint)

CutAggregator kulcsa:

    materialBarcode + requiredLength + handlerSide

KitAggregator kulcsa:

    materialBarcode

Tehát:

-   vágásnál: barcode + hossz + handlerSide,
-   kittingnél: csak barcode.

Nem része a kulcsnak: ownerName, colorName, fullWidth, fullHeight.

Pontosítás – WorksheetNeed és OrderNeed kapcsolata

A jelenlegi implementációban:

    ws.worksheetId = orderNeed.orderId;

Ez azt jelenti, hogy a WorksheetNeed 1:1 kapcsolatban áll egy Orderrel,
és nem külön entitás:
a WorksheetNeed gyakorlatilag az OrderNeed „gyártási nézete”.

A WorkOrder / WorkOrderNeed bevezetése után a WorksheetNeed szerepe
változni fog,
és a worksheetId nem az Order azonosítója lesz, hanem egy önálló
WorkOrder‑szintű azonosító.

3. Folyamatok (end‑to‑end)

1.  Felhasználó rögzíti az Order metaadatokat (orderNumber,
    customerName, orderDate).
2.  Hozzáad OrderLine / OrderItem tételeket:
    -   productId, méretek, handlerSide, externalId, ownerName,
        colorName,
    -   qty (OrderItem.order_qty).
3.  Az Order mentésre kerül (jövőbeli
    orders/repository/order_repository).

------------------------------------------------------------------------

3.2. OrderNeed előállítása (jelenlegi kód)

Jelenlegi implementáció (OrderNeedBuilder::build):

    OrderNeed OrderNeedBuilder::build(const Order& order, bool debug)
    {
        OrderNeed out;
        out.orderId = order.orderId;

        for (const auto& item : order.items) {

            OrderItemNeed oin;
            oin.orderItemId = item.orderItemId;
            oin.line = item.line;
            oin.itemNeeds.reserve(item.order_qty);

            for (int i = 0; i < item.order_qty; ++i) {
                ItemNeed n = NeedCalculator::calculate(item.line, item.modeName, debug);
                oin.itemNeeds.append(n);
            }

            out.orderItemNeeds.append(oin);
        }

        return out;
    }

Lépések:

1.  OrderNeedBuilder::build(order, debug) meghívása.
2.  Minden OrderItem‑re:
    -   ItemNeed perOne = NeedCalculator::calculate(line, modeName,
        debug),
    -   perOne ismétlése order_qty‑szer,
    -   minden példány külön ItemNeed az OrderItemNeed.itemNeeds
        vektorban.
3.  OrderNeed összeállítása.

------------------------------------------------------------------------

3.3. WorksheetNeed előállítása (jelenlegi kód)

Jelenlegi implementáció (WorksheetBuilder::fromOrderNeed):

-   OrderNeed → Piece / KitItem lista → aggregálás.

Lépések:

1.  WorksheetNeed ws; ws.worksheetId = orderNeed.orderId;
2.  Minden OrderItemNeed / ItemNeed:
    -   RawCut → Piece (materialBarcode, requiredLength, handlerSide,
        externalRef, ownerName, colorName, fullWidth, fullHeight),
    -   RawKit → KitItem (materialBarcode, quantity, ownerName,
        colorName, fullWidth, fullHeight).
3.  ws.cuts = CutAggregator::aggregate(pieces);
4.  ws.kits = KitAggregator::aggregate(kits);

Eredmény: egy Order teljes, aggregált gyártási listája.

Pontosítás – externalRef jelenlegi viselkedése

A kódban:

    p.externalRef = line.externalId;

Nincs példány‑szintű sorszámozás (X1.1, X1.2).
Ha ez üzleti igény lesz, külön v2 kiterjesztésként vezethető be.

3.4. WorkOrder létrehozása

3.4. WorkOrder létrehozása (jövőmodell)

1.  Felhasználó kiválaszt több Order‑t.
2.  Rendszer generál egy workOrderNumber‑t (lásd 5. fejezet).
3.  WorkOrder mentése (workorder/service/work_order_number_generator,
    workorder/repository).

3.5. WorkOrderNeed előállítása

1.  WorkOrderNeedBuilder::build(workOrder, modeName, debug).
2.  Betölti az összes Order‑t a workOrder.orderIds alapján.
3.  Minden Order‑re meghívja az OrderNeedBuilder::build‑et.
4.  Összefűzi az összes OrderNeed‑et.
5.  Az összes Piece / KitItem listát aggregálja:
    -   CutAggregator::aggregate,
    -   KitAggregator::aggregate.
6.  Eredmény: teljes gyártási lista WorkOrder szinten.

------------------------------------------------------------------------

4. Számítási logika (NeedCalculator)

A NeedCalculator jelenlegi viselkedése:

-   feltölti a DSL változókat (w, h, handler, owner, color, externalId,
    product),
-   futtatja a FormulaEngine‑t,
-   kiolvassa a len, qty, mat változókat,
-   visszaad egy ItemNeed‑et, amely RawCut és RawKit elemeket tartalmaz.

Fontos:

-   a qty szorzás nem itt történik, hanem:
    -   vágásnál: RawCut.cutting_qty mezőben jelenik meg (formula dönt),
    -   kittingnél: RawKit.kitting_qty mezőben,
    -   a rendelési darabszám (order_qty) szorzása az
        OrderNeedBuilder‑ben történik.

Pontosítás – RawCut / RawKit qty mezők

-   Cutting: qty opcionális
    -   ha nincs qty → cutting_qty = 1
    -   ha van qty → formula tölti
-   Kitting: qty kötelező
    -   ha nincs qty → hiba

⭐ 5. Munkalapszám generálás (WorkOrderNumberGenerator)

Formátum:

    YYYY-XXXX

ahol:

-   YYYY = év (pl. 2026),
-   XXXX = év elejétől folyamatosan növekvő sorszám (0001–9999).

Szabályok:

1.  A sorszám minden évben újraindul.
2.  Éven belül monoton növekvő.
3.  Lexikografikusan rendezhető.
4.  Könnyen kereshető.
5.  Nem tartalmaz konkrét dátumot.
6.  Gyártási gyakorlatban bevált modell.

Pontosítás – perzisztencia forrás

A WorkOrderNumberGenerator az aktuális év utolsó sorszámát
egy perzisztens tárolóból (pl. workorder tábla vagy külön számláló
tábla)
olvassa ki, és atomikusan növeli.

7. Miért jó ez a modell?

-   Tiszta rétegek: Order → Need → Worksheet / WorkOrder.
-   NeedCalculator egyszerű marad: csak egy darabra számol, nem
    foglalkozik qty‑vel.
-   Builder réteg felel a qty‑ért és aggregálásért: OrderNeedBuilder,
    WorksheetBuilder, WorkOrderNeedBuilder.
-   WorkOrder domain megjelenik: gyártási valóság leképezhető (több
    order egy munkalapon).
-   Auditálhatóság: OrderNeed / WorksheetNeed / WorkOrderNeed struktúrák
    végigkövethetővé teszik az utat.
-   UI/OrderWorkbench később ráültethető: a mostani pipeline már stabil,
    erre lehet egy OrderWorkbench UI‑t tervezni (order fej + tételek,
    keresés/szűrés, később query builder).
