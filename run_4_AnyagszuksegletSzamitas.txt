📘 Funkcionális specifikáció v2

NeedCalculationDetail mátrix validáció, generálás és UX‑jelzés

🎯 Cél

A rendszer biztosítsa, hogy minden terméktípushoz a
Product × Mode × Material mátrix:

-   mindig teljes legyen,
-   a felhasználó soha ne találkozzon hiányzó detail cellával,
-   a hiányok és hibák vizuálisan egyértelműek legyenek,
-   a rendszer auditálható és determinisztikus maradjon,
-   a GUI segítse a navigációt és a hibák megtalálását.

A rendszer legyen:

-   önjavító,
-   auditálható,
-   UX‑barát,
-   skálázható,
-   determinista.

------------------------------------------------------------------------

1) Fogalmi modell

1.1 A mátrix definíciója

A mátrix három dimenzióból áll:

-   ProductMaster (terméktípus)
-   NeedCalculation (számítási mód)
-   MaterialMaster (anyag)

Egy cella = egy NeedCalculationDetail rekord.

Egy detail akkor érvényes, ha:

-   van id (GUID)
-   van needCalculationId
-   van materialId
-   van formula
-   van kind (Cutting/Kitting)
-   a formula valid (szintaktikailag helyes)

1.2 A mátrix anyaghalmaza

A mátrix sorai kizárólag a NeedRule kapcsolatokból származnak:

  MaterialMaster halmaz = NeedRule.rightId halmaz

Ez a BOM‑logikával és a projektkóddal is összhangban van.

1.3 A mátrix teljessége

A mátrix akkor teljes, ha:

  minden termék × minden mód × minden anyag
  kombinációhoz létezik legalább egy detail rekord.

------------------------------------------------------------------------

2) Rendszer viselkedése

2.1 Startup

A rendszer:

-   csak validál,
-   nem generál,
-   összeállít egy globális hiánylistát,
-   audit logot készít,
-   a GUI még nem jelez hiányt.

Ez biztosítja, hogy a CSV import hibái nem fedődnek el.

2.2 Termékválasztáskor (lokális önjavítás)

A rendszer:

1.  Validálja a termék mátrixát
2.  Ha nincs hiány → nincs teendő
3.  Ha van hiány →
    -   a GUI jelzi a módnál (⚠️)
    -   a rendszer automatikusan generálja a hiányzó detail cellákat
    -   a registry frissül
    -   a GUI frissül
    -   audit log készül

Ez a „lokális önjavítás”.

2.3 Admin funkció: „Generate all missing details”

-   globális validáció
-   minden hiányzó cella generálása
-   audit log
-   GUI frissítés

------------------------------------------------------------------------

3) GUI viselkedés – új UX‑modell

A mátrix‑komplettség jelzése nem a torony overlay feladata.
A torony overlay csak repoCount/visibleRows alapján működik.

A mátrix‑komplettség jelzése három szinten történik:

------------------------------------------------------------------------

3.1 Módok listája (NeedCalculations)

Minden mód mellett egy ikon:

-   🔴 ha legalább egy anyaghoz nincs detail
-   🟡 ha unknown formula van, de minden cella létezik
-   🟢 ha minden formula valid

Ez az ikon jelzi, hogy abban a módban van‑e még dolgunk.

------------------------------------------------------------------------

3.2 Detail lista (NeedCalculationDetails)

Minden sor (anyag) mellett:

-   ⚠️ (sárga) → formula unknown (üres string)
-   ❗ (piros) → formula invalid
-   ✏️ → kézzel megadott, valid formula
-   nincs ikon → minden rendben

Ez a cellaszintű jelzés.

------------------------------------------------------------------------

3.3 Detail toolbar – globális mátrix állapot

A detail panel toolbarján:

-   🔴 = a mód teljesen hiányos vagy hibás
-   🟡 = részben hiányos (unknown formula van)
-   🟢 = teljes és valid

Ez a felhasználó számára a „mód egészségi állapota”.

🟧 3. MatrixGenerator implementálása

Felelőssége:

-   MissingDetail → NeedCalculationDetail rekordok generálása
-   default formula = "unknown" (nem "w-0")
-   default kind = Cutting
-   audit logolás

matrix_generator.cpp

    bool MatrixGenerator::generate(const QVector<MissingDetail>& list) {
        for (const auto& m : list) {
            NeedCalculationDetail d;
            d.id = QUuid::createUuid();
            d.needCalculationId = m.modeId;
            d.materialId = m.materialId;
            d.formula = "unknown";
            d.kind = NeedCalculationDetail::DetailKind::Cutting;

            NeedCalculationDetailRegistry::instance().insert(d);

            zEventINFO(QString("🟡 Auto-generated detail: product=%1 mode=%2 material=%3")
                .arg(m.productId.toString(), m.modeId.toString(), m.materialId.toString()));
        }
        return true;
    }
