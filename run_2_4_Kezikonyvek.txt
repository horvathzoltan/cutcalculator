✅ Felhasználói és Fejlesztői kézikönyvek

-   a felhasználói kézikönyv → a végfelhasználóknak
-   a fejlesztői kézikönyv → a fejlesztőknek, maintainereknek, új
    csapattagoknak

-   teljesen külön kezeli a két célcsoportot
-   ipari szintű dokumentációt eredményez
-   a projekted stílusához illeszkedik
-   Copilot‑optimalizált
-   moduláris
-   bármikor újra használható
-   hosszú távon fenntartható dokumentációs kultúrát épít

------------------------------------------------------------------------

✅ 1) Felhasználói kézikönyv prompt (User Manual Prompt)

Ez a prompt végfelhasználóknak szóló dokumentációt generál — egyszerű,
érthető, képernyőképekre felkészített, lépésről lépésre vezető
stílusban.

Másolható:

    Kérlek, készíts egy teljes, professzionális felhasználói kézikönyvet
    a következő funkcióhoz / modulhoz / alkalmazáshoz:

    [NÉV / FUNKCIÓ LEÍRÁSA]

    A kézikönyv legyen:
    - érthető nem fejlesztők számára is
    - lépésről lépésre vezető
    - képernyőképekre felkészített (ahol releváns)
    - magyar nyelvű
    - barátságos, de professzionális hangvételű
    - jól strukturált, Markdown formátumban

    A dokumentum tartalmazza:

    📘 Bevezetés
    🎯 A funkció célja
    🖥️ Rendszerkövetelmények
    🚀 Első lépések
    🧭 Navigáció és felület
    ✅ Alapműveletek
    ⚙️ Haladó funkciók
    💡 Tippek és trükkök
    ❗ Gyakori hibák és megoldások
    🔐 Adatkezelés és biztonság
    📁 Fájlkezelés (ha releváns)
    🧩 Integráció más modulokkal
    ❓ GYIK
    📞 Támogatás / Kapcsolat

    A kézikönyv legyen teljes, önállóan érthető, és ne tartalmazzon fejlesztői szintű részleteket.

------------------------------------------------------------------------

✅ 2) Fejlesztői kézikönyv prompt (Developer Manual Prompt)

Ez a prompt a fejlesztőknek szóló, mély technikai dokumentációt generál
— architektúra, modulok, API-k, folyamatok, snapshot/fallback logika,
audit, stb.

Másolható:

    Kérlek, készíts egy teljes, ipari szintű fejlesztői kézikönyvet
    a következő modulhoz / alrendszerhez / funkcióhoz:

    [NÉV / FUNKCIÓ LEÍRÁSA]

    A kézikönyv legyen:
    - fejlesztőknek szóló
    - részletes, technikai
    - architektúra-központú
    - moduláris
    - auditálható
    - Markdown formátumú
    - a CutCalculator projekt stílusához igazodó

    A dokumentum tartalmazza:

    📘 Bevezetés
    🎯 Cél és kontextus
    🏗️ Architektúra áttekintés
    📦 Modulok és felelősségi körök
    🧩 Adatmodellek
    🔄 Folyamatok (startup, shutdown, restore, save, event flow)
    🧠 Guardok, edge case-ek, deferred logika
    📁 Fájlszerkezet és projektstruktúra
    🔌 API-k és interfészek
    🛠️ Implementációs részletek
    🧪 Tesztelési stratégia
    📊 Audit logika
    🧱 Bővíthetőség és jövőbeli irányok
    🚧 Ismert korlátok
    📚 Kapcsolódó modulok
    🧭 Integrációs útmutató
    📌 Példák és best practice-ek

    A dokumentum legyen teljes, önállóan érthető, és alkalmas új fejlesztők onboardingjára.

------------------------------------------------------------------------

Zoltán, akkor jöjjön a Kézikönyv‑generálási Workflow, ábra nélkül, de
olyan tisztán és ipari szinten összerakva, hogy akár egy nagyvállalati
dokumentációs csapat is elégedetten csettintene.

Ez a workflow két külön világot kezel:

-   Felhasználói kézikönyv (User Manual)
-   Fejlesztői kézikönyv (Developer Manual)

Mindkettő más ritmusban, más mélységben, más célközönségnek készül — de
a workflow közös alapokra épül.

------------------------------------------------------------------------

🧭 Kézikönyv‑generálási Workflow (ipari szintű, ábra nélkül)

A workflow 6 lépésből áll, és minden lépés kristálytisztán meghatározza,
hogy mit csinálunk, miért, és milyen outputot várunk.

------------------------------------------------------------------------

✅ 1. lépés — Cél meghatározása (User vagy Developer Manual?)

Minden kézikönyv generálása előtt tisztázzuk:

-   Ki a célközönség?
    -   végfelhasználó → User Manual
    -   fejlesztő / maintainer → Developer Manual
-   Mi a dokumentum fókusza?
    -   egy funkció
    -   egy modul
    -   egy alrendszer
    -   egy teljes alkalmazás

Ez a lépés dönti el, melyik promptot használjuk.

Output:
✅ „User Manual” vagy „Developer Manual” döntés
✅ fókusz meghatározása

------------------------------------------------------------------------

✅ 2. lépés — Input összegyűjtése (a dokumentum alapja)

A Copilot csak abból tud dolgozni, amit lát.
Ezért a dokumentum generálása előtt összegyűjtjük:

Felhasználói kézikönyvhöz:

-   UI screenshotok (ha vannak)
-   funkció leírása
-   user flow
-   edge case-ek
-   tipikus hibák
-   menüpontok, gombok, ikonok

Fejlesztői kézikönyvhöz:

-   architektúra dokumentum (kettes)
-   modulok listája
-   fájlstruktúra
-   API-k
-   folyamatok
-   snapshot/fallback logika
-   audit logika
-   diff vagy commit lista (ha új modul)

Output:
✅ összegyűjtött inputok listája
✅ releváns fájlok / modulok

------------------------------------------------------------------------

✅ 3. lépés — Prompt kiválasztása és futtatása

Most jön a két prompt közül a megfelelő:

-   User Manual Prompt → végfelhasználóknak
-   Developer Manual Prompt → fejlesztőknek

A promptot mindig a 2. lépésben összegyűjtött inputokkal futtatjuk.

Output:
✅ első generált verzió (v1)
✅ teljes kézikönyv draft

------------------------------------------------------------------------

✅ 4. lépés — Review és finomhangolás (közös munka)

A generált dokumentumot átnézzük:

-   pontos?
-   érthető?
-   hiányzik valami?
-   túl hosszú?
-   túl technikai?
-   túl kevés technikai?
-   kell hozzá screenshot hely?
-   kell hozzá példakód?

Ez a lépés a közös iteráció.

Output:
✅ v2 verzió
✅ tisztított, pontosított dokumentum

------------------------------------------------------------------------

✅ 5. lépés — Véglegesítés és formázás

A dokumentumot:

-   formázzuk
-   tagoljuk
-   hozzáadjuk a tartalomjegyzéket
-   egységesítjük a stílust
-   ellenőrizzük a hangnemet
-   ellenőrizzük a konzisztenciát

Ez a lépés teszi „kiadhatóvá”.

Output:
✅ végleges kézikönyv (v3)
✅ Markdown formátumban

------------------------------------------------------------------------

✅ 6. lépés — Publikálás és verziózás

A végleges kézikönyvet:

-   betesszük a docs/ mappába
-   verziózzuk (pl. user_manual_v1.0.md)
-   hivatkozást teszünk a README-be
-   opcionálisan changelogot vezetünk

Output:
✅ dokumentum a projektben
✅ verziózott, visszakereshető állapot

------------------------------------------------------------------------

✅ A workflow röviden (bulletpontokban)

-   🎯 cél meghatározása
-   📥 inputok összegyűjtése
-   🤖 prompt futtatása
-   🔍 review + iteráció
-   🧽 véglegesítés
-   📦 publikálás
