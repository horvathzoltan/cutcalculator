🎯 1. Bevezetés

A CutCalculator UI‑state rendszere 2026‑ra teljesen megújult.
A korábbi SnapshotManager + LayoutDefaultStore + fallback baseline
modell helyett egy:

-   moduláris,
-   handler‑alapú,
-   audit‑ready,
-   percent‑based,
-   diff‑barát,
-   kiterjeszthető

UI‑state engine működik.

A cél:

-   minden UI‑elem állapota menthető legyen
-   minden állapot emberi olvasható legyen
-   minden widget auditálható legyen
-   minden widget determinisztikusan visszaálljon
-   a rendszer automatikusan jelezze a hiányzó vagy hibás állapotokat

------------------------------------------------------------------------

🧩 2. Rendszerfilozófia

A rendszer három alapelvre épül:

1) Minden widgetnek van állapota

Ha layout‑kritikus → mentjük.
Ha nem → kihagyjuk.

2) Minden widgethez tartozik egy handler

A handler felelős:

-   state extract
-   state restore
-   percent‑math
-   audit log
-   validáció

3) A state fájl emberi olvasható és diff‑barát

Minden kulcs:

-   widget objectName alapján
-   emberi olvasható
-   stabil (nem index‑alapú)

🏗️ 3. Architektúra áttekintés

    UIStateCollector
        ├── WidgetDiscovery (Phase 1: collect)
        ├── WidgetDiscovery (Phase 2: classify)
        ├── HandlerRegistry
        │       ├── SplitterHandler
        │       ├── HeaderHandler
        │       ├── GeometryHandler
        │       ├── ScrollAreaHandler
        │       └── Custom handlers…
        ├── StateExtractor
        ├── StateRestorer
        └── AuditLogger

A régi SnapshotManager → teljesen megszűnt.
A fallback baseline → megszűnt.
A monitorprofil‑logika → kivezetve.

------------------------------------------------------------------------

🔌 4. Handler‑alapú UI‑state modell

Minden widgethez egy handler tartozik.

Példa:

  Widget típusa   Handler
  --------------- -------------------
  QSplitter       SplitterHandler
  QHeaderView     HeaderHandler
  QMainWindow     GeometryHandler
  QScrollArea     ScrollAreaHandler
  CustomWidget    saját handler

A handler:

-   felismeri a widgetet
-   kimenti az állapotot
-   visszaállítja az állapotot
-   validál
-   auditál

------------------------------------------------------------------------

🔍 5. Widget Discovery (2‑fázisú)

Fázis 1 — Gyűjtés

Rekurzívan bejárjuk a widget‑fát.

-   minden widget bekerül
-   objectName audit
-   unnamed widget → __unnamed_<type>_<id> audit marker

Fázis 2 — Osztályozás

A handler registry dönti el:

-   melyik widgethez melyik handler tartozik
-   mely widget layout‑kritikus
-   mely widget ignorálható

------------------------------------------------------------------------

🧮 6. Percent‑based state formátum

Minden érték:

-   százalékos
-   emberi olvasható
-   diff‑barát

Példák:

    splitter: "70.0%,30.0%"
    header:   "25.0%,50.0%,25.0%"
    geometry: "10%,10%,80%,80%"

------------------------------------------------------------------------

🗂️ 7. State fájl szerkezete

Fő elvek

-   minden kulcs: objectName
-   minden érték: percent string
-   minden hiányzó handler → audit marker
-   minden unnamed widget → audit marker

Példa state fájl:

    [MainWindow]
    geometry = "10%,10%,80%,80%"

    [BOMWorkbench]
    leftSplitter = "30.0%,70.0%"
    rightSplitter = "60.0%,40.0%"
    treeHeader = "20.0%,40.0%,40.0%"

    [Audit]
    missingHandlers = ["ColorEditorPanel"]
    unnamedWidgets = ["__unnamed_QSplitter_42"]

------------------------------------------------------------------------

🔄 8. Mentés és visszaállítás folyamata

Mentés

1.  WidgetDiscovery (phase 1)
2.  WidgetDiscovery (phase 2)
3.  HandlerRegistry → handler kiválasztása
4.  Handler.extract()
5.  Audit log
6.  State fájl írása

Visszaállítás

1.  State fájl beolvasása
2.  WidgetDiscovery
3.  HandlerRegistry
4.  Handler.restore()
5.  Deferred restore, ha szükséges
6.  Audit log
