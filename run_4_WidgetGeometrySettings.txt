📋 Követelményspecifikáció (frissített)

-   Splitter állapotok:
    -   Mentés arányosan (százalékban), nem bináris blobként.
    -   Példa: main_splitter_state=70,30 → bal panel 70%, jobb panel
        30%.
    -   Több gyerek esetén lista: 50,30,20.
-   Ablak geometriák:
    -   Mentés százalékban a képernyőhöz viszonyítva (x%, y%, w%, h%).
    -   Példa: window_geometry=10%,10%,80%,80%.
    -   Így mindig arányosan újraméretezhető.
-   Screen méret mentése:
    -   Leálláskor elmentjük az aktuális képernyő méretet (pl.
        screen_size=1920x1080).
    -   Induláskor összevetjük a mentettel.
    -   Ha eltérés van → log + újraméretezés.
-   Futás közbeni detektálás:
    -   QScreen::geometryChanged esemény figyelése.
    -   Ha változik → ugyanaz a funkció fut, mint induláskor.
-   Audit log:
    -   Minden mentés és visszaállítás explicit logolva van (zEventINFO,
        zEventWARN).
    -   Példa: "✅ Splitter state saved: 70,30" vagy
        "⚠️ Invalid geometry, fallback 60% screen".

------------------------------------------------------------------------

⚙️ Funkcionális specifikáció (frissített)

-   Mentéskor:
    -   Splitter → sizes() → arányos lista → string.
    -   Ablak → geometry() → screen méret → százalékos értékek.
    -   Screen méret → QScreen::size() → string.
-   Visszaállításkor:
    -   Splitter → string parse → setSizes().
    -   Ablak → százalékos értékek × aktuális screen méret →
        setGeometry().
    -   Screen méret összevetés → ha változott, újraszámolás.

------------------------------------------------------------------------

🛠️ Implementációs terv

1.  SettingsStore/Manager bővítése
    -   Új kulcs: screen_size.
    -   Getter/setter százalékos ablakgeometriára.
    -   Getter/setter arányos splitter állapotra.
2.  BOMWorkbench módosítása
    -   saveState() → splitter arányok + ablak százalékos geometriák +
        screen méret.
    -   restoreState() → összevetés + újraszámolás.
3.  Event wiring
    -   QScreen::geometryChanged → hívja az adjustWindowGeometry()
        függvényt.
    -   Induláskor is hívjuk ugyanezt, ha screen változott.

Szeretnéd, hogy adjak egy konkrét adjustWindowGeometry() implementációt,
ami százalékos értékekből számolja újra az ablakot?
*********************************
Pontosan 🎯 — a „15px jelenség” tipikus tünete annak, hogy a restore túl korán fut, amikor a splitter még nem kapott tényleges méretet. A helperen tényleg érdemes finomítani, hogy a jövőben ne kelljen mindenhol kézzel showEvent‑be tenni a restore‑t.

---

## Mit lehet beépíteni a helperbe?

### 1. **Guard check a totalPixels‑re**
Ha a `splitter->size().width()` vagy `height()` túl kicsi (pl. < 50px), akkor ne állíts vissza azonnal, hanem halaszd későbbre:

```cpp
if (totalPixels < 50) {
    QTimer::singleShot(0, splitter, [splitter, percentState]() {
        GeometryHelper::restoreSplitterState(splitter, percentState);
    });
    zEventWARN("⚠️ Splitter restore postponed: size too small");
    return;
}
```

Így a helper maga gondoskodik arról, hogy ne legyen 15px‑es állapot.

---

### 2. **Kezdeti fallback értelmes elosztással**
Ha nincs értelmes méret, akkor ne 15px‑et osszon szét, hanem adjon egyenlő arányt, de nagyobb minimumot:

```cpp
if (totalPixels <= 0) {
    QList<int> equal(childCount, 100); // minden gyerek kapjon legalább 100px
    splitter->setSizes(equal);
    return;
}
```

---

### 3. **Stretch factor automatikus beállítása**
A helper beállíthatja a stretch factorokat is, hogy a Qt ne essen vissza abszurd defaultokra:

```cpp
for (int i = 0; i < childCount; ++i) {
    splitter->setStretchFactor(i, 1);
}
```

---

### 4. **Audit log finomítása**
Írd ki restore előtt a `totalPixels` értéket, így azonnal látod, ha túl kicsi:

```cpp
zEventINFO(QString("🔎 Splitter restore diag: total=%1, percent=%2")
           .arg(totalPixels).arg(percentState));
```

---

## Röviden

- A helperben legyen **méretellenőrzés**: ha túl kicsi, halassza későbbre.
- Adjon **értelmes fallbacket** (pl. 100px per child).
- Állítson be **stretch factorokat** automatikusan.
- Audit logban jelezze, ha halasztott restore történt.

---

🦎 Szaladgyík: így a GeometryHelper maga védi ki a „15px jelenséget”, és nem kell mindenhol külön showEvent‑be tenni a restore‑t. Ez lesz a következő finomítási feladatunk.
