Zoltán, tökéletesen értem, mit szeretnél:
összehozni a sok különböző időpillanatban született refaktor‑tervet
egyetlen, tiszta, modern, releváns, pontonként végrehajtható
MASTER‑tervvé, ahol:

-   ami már elkészült → kikerül
-   ami biztosan kell → benne marad
-   ami vitatható → külön listába kerül („döntendő”)
-   ami felesleges → kuka
-   ami előnyt hoz → prioritásba kerül

Ez most egy nagyon jó pillanat a konszolidációra, mert a rendszer
stabil, a fejünkben lévő architektúra tiszta, és a régi tervek között
vannak már teljesen elavult, részben teljesült, vagy már meghaladott
pontok.

Úgyhogy most csináljuk meg azt, amit egy senior architect ilyenkor
csinálna:

⭐ A teljes refaktor‑terv konszolidálása

(a legfrissebb terv + a korábbiak összeolvasztása → új, tiszta,
végrehajtható MASTER‑terv)

A folyamat három lépésből áll:

------------------------------------------------------------------------

🔵 1) A régi tervek teljes átnézése és kategorizálása

A három fő forrás:

1.  A legfrissebb „Nagy Refaktor Terv”
2.  A korábbi registry‑modernizációs tervek
3.  A NeedCalculation‑modul egységesítő terve

Mindegyik pontot besoroljuk:

-   [KEEP] – biztosan kell, előnyt hoz
-   [MAYBE] – vitatható, később döntünk
-   [DROP] – felesleges, elavult, már nem releváns
-   [DONE] – már elkészült

------------------------------------------------------------------------

🔵 2) A [KEEP] pontokból új, tiszta, lineáris MASTER‑terv készítése

Ez lesz a ténylegesen végrehajtandó refaktor‑terv, amit holnaptól
lépésenként végigviszünk.

------------------------------------------------------------------------

🔵 3) A [MAYBE] pontok külön listába kerülnek („Döntendő backlog”)

Ezeket később, nyugodt fejjel döntjük el.

------------------------------------------------------------------------

⭐ Most jön a lényeg: a teljes konszolidáció

(fejből dolgozom, mert minden pontot együtt építettünk fel)

------------------------------------------------------------------------

🟩 A teljes refaktor‑terv kategorizálva

✔ [KEEP] – Ezeket biztosan végigvisszük (előnyt hoznak, haladást jelentenek)

1) NeedRule import hibakezelés finomítása

-   fatal → részleges siker támogatása
-   startup stabilitás
-   CSV‑pipeline egységesítés

2) NeedCalculationRepository + DetailRepository path‑modernizálás

-   FileNameHelper integráció
-   hardcoded path megszüntetése
-   CSV‑pipeline egységesítése

3) NeedCalculationRegistry + DetailRegistry egységesítése

-   constructor tisztítás
-   onLoadLog()
-   persist logolás
-   domain hookok egységesítése

4) CalculationModesManager + CalculationModeDetailManager tisztítása

-   load felelősség managerben
-   registry tiszta marad
-   UI stabilizálása

5) Repository‑egységesítés (NeedCalculation + NeedRule mintájára)

-   FileContext
-   fejléc ellenőrzés
-   sorhiba kezelés
-   audit log

6) Új Registry Fejlettségi Mátrix (modern architektúra szerint)

-   mixin‑alapú képességek
-   workflow‑policy
-   audit pipeline
-   lookup API

------------------------------------------------------------------------

🟨 [MAYBE] – Vitatható, később döntünk róla

1) RegistryManager meta‑szintű bővítése

-   capability‑detektálás
-   registry‑kategóriák automatikus felismerése
-   audit riport bővítése
    → jó lenne, de nem sürgős

2) Generikus CsvRepository / ConnectionImporter visszahozása

-   elegáns, de nem kritikus
-   a modern architektúrával kompatibilis
    → később döntünk

3) Dokumentáció + architektúra térkép

-   fontos, de nem blokkol semmit
    → később

4) OverlayIconWidget globális integráció

-   UX‑szépítés
    → később

------------------------------------------------------------------------

❌ [DROP] – Felesleges, elavult, már nem releváns

1) Régi engine‑típusok visszahozása

-   IdentifiableRegistryEngine
-   ConnectionRegistryEngine
    → már modernizáltuk, nincs értelme visszamenni

2) Régi NeedRuleTraits / ProductTraits / MaterialTraits visszahozása

→ a modern architektúra tisztább

3) Régi hierarchia‑kezelés visszahozása

→ HierarchyMixin már működik

4) Régi barcode‑lookup visszahozása

→ BarcodeIndexMixin sokkal jobb

------------------------------------------------------------------------

🟦 [DONE] – Már elkészült

-   BarcodeLookupMixin
-   BarcodeIndexMixin
-   HierarchyMixin
-   NeedRuleRegistry modernizálása
-   MaterialRequirementsView fix
-   NeedCalculationDetailRegistry engine‑alapú workflow
-   RegistryEngine / RegisterMe stabilizálása
-   Registry audit pipeline
-   Snapshot / Layout / GeometryHelper
-   OverlayIconWidget pipeline
-   Logger subsystem
-   Material/Product pipeline
-   Test framework

------------------------------------------------------------------------

⭐ ÚJ, TISZTA, VÉGREHAJTHATÓ MASTER‑TERV

(csak a [KEEP] pontokból)

1) NeedRule import hibakezelés finomítása

2) NeedCalculationRepository + DetailRepository path‑modernizálás

3) NeedCalculationRegistry + DetailRegistry egységesítése

4) CalculationModesManager + DetailManager tisztítása

5) Repository‑egységesítés (NeedCalculation + NeedRule)

6) Új Registry Fejlettségi Mátrix elkészítése

Ez a hat pont a következő sprint.
Mindegyik előnyt hoz, mindegyik haladást jelent, és együtt lezárja a
nagy refaktort.

------------------------------------------------------------------------
