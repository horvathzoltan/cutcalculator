Zoltán, most nagyon pontosan látod a problémát, és teljesen igazad van:
a jelenlegi OverlayHelper nem jó irány, mert rossz helyen próbál
megoldani valamit, amit valójában a Presenter‑szintű overlay‑logika
tartalmaz.

A helyes irány az, amit most kimondtál:

🟣 **Nem a helperből kell „okos overlayt” csinálni,

hanem a Presenter‑ben lévő overlay‑logikát kell kiszervezni egy egységes
helperbe.**

Ez a kulcs.

A jelenlegi OverlayHelper:

-   túl alacsony szinten működik (UI layout manipuláció)
-   nem egységesíti a Presenter‑szintű overlay‑logikát
-   nem oldja meg a torony‑szintű overlay‑frissítést
-   nem kezeli a repoCount / visibleRows logikát
-   nem kezeli a domain‑specifikus overlay‑állapotokat
-   nem oldja meg a pointer‑felülírás problémát
-   nem oldja meg a toolbar vs view overlay dilemmát

Amit viszont te most felismertél:

🟢 A Presenter‑ben lévő overlay‑frissítési logika a valódi „overlay policy”.

És ezt kell helperbe szervezni.

------------------------------------------------------------------------

🟣 Mi a jelenlegi Presenter‑logika?

Ez:

    void CalculationModesPresenter::refreshOverlayOnly()
    {
        int repo = NeedCalculationRegistry::instance().size();
        OverlayHelper::update(_status, repo, _view->rowCount());
    }

És ez:

    void OverlayIconWidget::updateOverlayState2(int repoCount, int totalRows)
    {
        setBaseEmoji("📄");

        if (repoCount == 0) {
            setOverlay(BottomRight, "❌");
            return;
        }

Ez a kettő együtt alkotja a torony‑szintű overlay policy‑t.

Ez az, amit helperbe kell szervezni.

------------------------------------------------------------------------

🟢 A helyes irány: új OverlayStatusHelper (Presenter‑szintű helper)

Ez NEM UI helper.
Ez NEM layout helper.
Ez NEM widget helper.

Ez egy domain‑vezérelt overlay policy helper, amely:

-   bemenet: repoCount, visibleRows, esetleg domain‑specifikus állapotok
-   kimenet: milyen overlay ikon legyen
-   a widgetet csak beállítja, nem helyezi el
-   a Presenter hívja
-   minden toronyban egységes

------------------------------------------------------------------------

🟣 Új helper API (tervezet)

    class OverlayStatusHelper {
    public:
        enum class State {
            EmptyRepo,
            NoVisibleRows,
            Normal
        };

        static State computeState(int repoCount, int visibleRows);

        static void apply(OverlayIconWidget* w, State s);
    };

------------------------------------------------------------------------

🟢 computeState implementáció

    OverlayStatusHelper::State OverlayStatusHelper::computeState(int repoCount, int visibleRows)
    {
        if (repoCount == 0)
            return State::EmptyRepo;

        if (visibleRows == 0)
            return State::NoVisibleRows;

        return State::Normal;
    }

------------------------------------------------------------------------

🟢 apply implementáció

    void OverlayStatusHelper::apply(OverlayIconWidget* w, State s)
    {
        if (!w) return;

        w->setBaseEmoji("📄");

        switch (s) {
        case State::EmptyRepo:
            w->setOverlay(OverlayIconWidget::BottomRight, "❌");
            break;

        case State::NoVisibleRows:
            w->setOverlay(OverlayIconWidget::BottomRight, "🟡");
            break;

        case State::Normal:
            w->setOverlay(OverlayIconWidget::BottomRight, "🟢");
            break;
        }
    }

------------------------------------------------------------------------

🟣 Presenter‑oldali használat

    void CalculationModesPresenter::refreshOverlayOnly()
    {
        int repo = NeedCalculationRegistry::instance().size();
        int visible = _view->rowCount();

        auto state = OverlayStatusHelper::computeState(repo, visible);
        OverlayStatusHelper::apply(_status, state);
    }

------------------------------------------------------------------------

🟢 Mi történik ezután az OverlayIconWidget::updateOverlayState2‑vel?

Két lehetőség:

A) Meghagyjuk, de deprecated

A helper hívja helyette.

B) Teljesen kivesszük

A Presenter‑szintű helper veszi át a szerepét.

Én a B) teljes eltávolítást javaslom, mert:

-   a widget ne tartalmazzon domain‑logikát
-   a widget csak rajzoljon
-   a Presenter döntsön az állapotról
-   a helper egységesítse a döntést

Ez a tiszta MVP.

------------------------------------------------------------------------

🟣 Mi legyen a jelenlegi OverlayHelper‑rel?

A jelenlegi OverlayHelper:

-   attachToView → maradhat, de csak panel‑szerű view‑khoz
-   createStatusWidget → maradhat
-   update → törölhető (mert a Presenter‑szintű helper veszi át)
-   warning / error → átkerülhet az új helperbe, vagy maradhat
    UI‑helperként

A helyes irány:

🟢 OverlayHelper = UI helper

🟢 OverlayStatusHelper = Presenter‑szintű overlay policy helper

Ez a kettő együtt adja a teljes overlay architektúrát.
