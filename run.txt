🔄 Frissített, végrehajtható terv

1.  Validációs kiegészítés a NeedRuleRegistry-ben
    -   NeedRuleRegistry::insert() előtt lefutnak a szabályok:
        -   Bal oldal létező Product legyen.
        -   Jobb oldal létező Material legyen.
        -   Tiltás: azonos barcode.
        -   Tiltás: duplikált kapcsolat.
    -   Ha bármelyik sérül → audit log hibaüzenet, és nem kerül be a
        kapcsolat.
2.  Audit üzenetek központosítása
    -   Központi helper (AuditMessages vagy NeedRuleErrorHelper).
    -   Függvények:
        -   invalidProduct(id, barcode)
        -   invalidMaterial(id, barcode)
        -   duplicateConnection(productBarcode, materialBarcode)
        -   sameBarcode(productBarcode)
    -   Így minden hibaüzenet egységes formátumban kerül a logba.
    -   Ha akarjuk, a BarcodeValidator üzenetkészletét is kiemelhetjük
        ide, és újrahasznosíthatjuk.
3.  CSV import hibák részletezése
    -   A ConnectionRepository::load() már jelzi, ha nem található
        entitás.
    -   Kiegészítés: azonos barcode esetén is ctx.addError(...) → így a
        hibakategóriákban külön látszik.
4.  UI hibajelzés
    -   MaterialRequirementsView::apply_row_visuals() csak runtime
        lookup hibát jelzi (pl. törölt Material).
    -   Import hibák nem kerülnek be → piros háttér nem lesz, de audit
        riportban látszik.
    -   Ez így rendben van, nem kell túlgondolni.
5.  Tesztadatok ellenőrzése
    -   Hibás CSV futtatása (ROL-RR,ROL-RR, TE-R-23,TE-R-23, stb.).
    -   Ellenőrizni:
        -   Audit logban részletes hibák jelennek meg.
        -   Registry-ben csak a valid sorok maradnak.
        -   UI piros háttér csak runtime lookup hibánál.

✨ Röviden

-   Validáció a NeedRuleRegistry-ben → készre jelölhető.
-   Audit üzenetek központosítása → egységes stringek, opcionálisan
    újrahasznosítva a BarcodeValidatorból.
-   Import hibák → audit riportban, runtime hibák → piros háttér a
    view-ban.
-   Nem kell túlgondolni: a specifikus hibák specifikus stringgel is
