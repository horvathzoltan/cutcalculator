⭐ IMPLEMENTÁCIÓS TERV

Cél: általános kifejezéskezelés a FormulaEngine-ben, minden DSL → függvény formára fordítva

1) A FormulaEngine NEM számol többé.

Csak fordít:

    DSL → Expression string → Expression::Parse() → Expression::Calculate()

2) A DSL fordító (dslToExpression) a kulcs.

Ez fogja felismerni:

-   w-10 → sub(w,10)
-   h-15 → sub(h,15)
-   w*h → mul(w,h)
-   (w*h)/1000 → div(mul(w,h),1000)
-   qty:fixed:3 → mul(qty,3)
-   choose: → if(...)
-   opt: → ignorálás vagy későbbi flag-kezelés

3) Általános aritmetikai kifejezések támogatása

Ehhez kell:

-   tokenizáló (változó, literál, operátor, zárójel)
-   shunting-yard (precedencia + zárójelek)
-   AST építés
-   AST → Expression string fordító

Ez a rész lesz a „motor”.

4) A choose: operátor Expression formára fordítása

Példa:

    choose: (w*h > 1000000) ? A : B
    → if(gt(mul(w,h),1000000), A, B)

5) Az opt: részek leválasztása

A fő kifejezés:

    h-10 + opt:paint:+40
    → h-10

A többi ignorálható, amíg nincs flag-kezelés.

6) A FormulaEngine::eval() végül így néz ki:

    QString expr = dslToExpression(f);
    Expression e = Expression::Parse(expr);
    QVariant v = e.Calculate();

⭐ TOKEN SNAPSHOT

(ez a „hogyan fog kinézni a tokenizálás” jegyzet)

A tokenizáló feladata:

Bemenet:

    (w-10) * (h-20) / 1000

Tokenek:

    [
      "(", "w", "-", "10", ")",
      "*",
      "(", "h", "-", "20", ")",
      "/",
      "1000"
    ]

Token típusok:

-   Identifier: w, h, qty, A, B
-   Number: 10, 20, 1000, 1e6, 5.5
-   Operator: +, -, *, /, >, <, >=, <=, ==
-   Paren: (, )
-   Keyword: opt:, choose:, len:, qty:fixed:, stb. (külön kezelve)
-   Whitespace: ignorálva

Operátorprecedencia:

1.  *, /
2.  +, -
3.  összehasonlítók: >, <, >=, <=, ==

Shunting-yard output (postfix):

    w 10 - h 20 - * 1000 /

AST:

            div
           /    \
         mul    1000
        /   \
     sub     sub
    /   \   /   \
    w   10 h    20

Expression string:

    div(
        mul(
            sub(w,10),
            sub(h,20)
        ),
        1000
    )

És ezt már tudja a meglévő Expression rendszer.

Patch terv – FormulaEngine átalakítása változó‑alapú működésre

Alapelv:
FormulaEngine ezentúl csak kifejezést kap (QString expr), minden input
és output a VariableRegistry‑n keresztül megy.

------------------------------------------------------------------------

1. FormulaEngine API átalakítása

Most:

    static EvaluatedFormula eval(const QString& f, int w, int h, int qty);

Lesz:

    static EvaluatedFormula eval(const QString& f);

Teendők

-   Minden eval(..., w, h, qty) hívást átírni úgy, hogy:
    -   a hívás előtt a VariableRepository‑be bekerüljenek:
        -   w, h, qty (és később bármi más: margin, area, stb.)
    -   a FormulaEngine::eval(f) már nem kapja meg ezeket paraméterként.

------------------------------------------------------------------------

2. evalExpressionGeneric átalakítása

Most:

    static QVariant evalExpressionGeneric(const QString& expr, int w, int h, int qty)
    {
        auto& vars = VariableRepository::instance();
        vars.set("w",   w);
        vars.set("h",   h);
        vars.set("qty", qty);
        ...
    }

Lesz:

    static QVariant evalExpressionGeneric(const QString& expr)
    {
        auto& vars = VariableRepository::instance();
        // itt már NEM állítunk be semmit, csak olvasunk
        ...
    }

Teendők

-   Kivenni a w/h/qty beállítását innen.
-   Mindenhol, ahol eddig evalExpressionGeneric(t, w, h, qty) volt,
    átírni evalExpressionGeneric(t)‑re.
-   Biztosítani, hogy a hívó fél már előtte feltöltötte a registry‑t.

------------------------------------------------------------------------

3. FormulaEngine::eval belső logika módosítása

Most:

    EvaluatedFormula FormulaEngine::eval(const QString& f, int w, int h, int qty)
    {
        ...
        // qty: DSL-ek w,h,qty alapján
        // choose: evalChoose(t, w, h, qty)
        // opt: evalWithOpt(t, w, h, qty)
        // általános kifejezés: evalExpressionGeneric(t, w, h, qty)
    }

Lesz:

    EvaluatedFormula FormulaEngine::eval(const QString& f)
    {
        EvaluatedFormula out;
        out.stringValue.clear();

        QString t = FormulaNormalizer::normalizeWhitespace(f);
        t = FormulaNormalizer::stripOuterParens(t);

        // szám literálok (ugyanaz maradhat)
        // qty: DSL-ek → VariableRepository-ből olvasott w,h,qty-vel számolnak
        // choose: → evalChoose(t)
        // opt: → evalWithOpt(t)
        // minden más → evalExpressionGeneric(t)

        return out;
    }

Teendők

-   Kivenni a w, h, qty paramétereket a függvény aláírásából és
    belsejéből.
-   A qty: DSL ágakban w és h értékét a VariableRepository‑ből
    kiolvasni:
    -   pl. vars.get("w").toInt() stb.
-   evalChoose és evalWithOpt aláírását is módosítani: csak
    const QString& t.

------------------------------------------------------------------------

4. evalChoose és evalWithOpt átalakítása

Most:

    EvaluatedFormula FormulaEngine::evalChoose(const QString& t, int w, int h, int qty);
    EvaluatedFormula FormulaEngine::evalWithOpt(const QString& t, int w, int h, int qty);

Lesz:

    EvaluatedFormula FormulaEngine::evalChoose(const QString& t);
    EvaluatedFormula FormulaEngine::evalWithOpt(const QString& t);

Belső változás

-   Ahol eddig eval(branch, w, h, qty) volt, ott most simán eval(branch)
    lesz.
-   A feltétel kiértékelése (condExpr) már így is az új pipeline‑on
    megy, csak a változókat most a registry‑ből veszi az Expression.

------------------------------------------------------------------------

5. VariableRepository használatának egységesítése

Teendők

-   Bevezetni egy konvenciót: minden FormulaEngine hívás előtt a hívó
    fél:
    -   törli vagy reseteli a releváns változókat (opcionális, ha kell),
    -   beállítja:
        -   w, h, qty,
        -   később: margin, extra, discount, stb.
-   A FormulaEngine soha többé nem állít be input változót, csak:
    -   olvas belőlük,
    -   és opcionálisan eredményt ír vissza (pl. result_length,
        result_pieces).

------------------------------------------------------------------------

6. area kezelésének előkészítése

Két lépésben:

6.1. Függvényként

-   Expression oldalon bevezetni egy area(a,b) függvényt:
    -   Function::area(double a, double b) { return a*b; }
-   A DSL‑ben használható lesz:
    -   area(w,h)/1000

6.2. Változóként (ha akarod)

-   A hívó fél (pl. NeedCalculator) induláskor:
    -   vars.set("area", w*h);
-   A formula:
    -   area / 1000

Első körben elég a függvényes verziót megcélozni.

------------------------------------------------------------------------

7. Hívó kódok átírása (NeedCalculator, tesztek)

NeedCalculator

Most:

    auto ev = FormulaEngine::eval(detail.formula, width, height, qty);

Lesz:

    auto& vars = VariableRepository::instance();
    vars.set("w", width);
    vars.set("h", height);
    vars.set("qty", qty);

    auto ev = FormulaEngine::eval(detail.formula);

FormulaEngineTester

Mindenhol, ahol:

    FormulaEngine::eval("w-15", 1200, 1500, 1);

→ átírni:

    auto& vars = VariableRepository::instance();
    vars.set("w", 1200);
    vars.set("h", 1500);
    vars.set("qty", 1);

    auto ev = FormulaEngine::eval("w-15");
