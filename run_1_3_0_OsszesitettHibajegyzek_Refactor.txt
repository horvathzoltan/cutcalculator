🎯 1. A gondolatod lényege

Azt mondod:

  „Mi lenne, ha nem lenne PieceNeed és KitNeed, hanem csak RawCut és
  RawKit, és az ItemNeed ezeket tartalmazná?”

Ez így nézne ki:

    struct ItemNeed {
        QVector<RawCut> cutPieces;  // nem aggregált
        QVector<RawKit> kitItems;   // nem aggregált
    };

Majd:

    struct OrderItemNeed {
        QUuid orderItemId;
        QVector<ItemNeed> itemNeeds; // minden példány külön
    };

    struct OrderNeed {
        QUuid orderId;
        QVector<OrderItemNeed> orderItemNeeds;
    };

És a NeedCalculator::calculate() csak egy példányt számol:

    ItemNeed NeedCalculator::calculate(const OrderLine& line);

🧠 2. Miért jó, hogy eltűnik a PieceNeed / KitNeed?

Mert:

-   RawCut = a formula eredménye → ez a legalsó, legnyersebb adat
-   RawKit = ugyanígy

Ezek a valódi outputjai a DSL-nek.

A PieceNeed / KitNeed csak egy „félúton kitalált” réteg volt, ami:

-   duplikálta az adatot,
-   keverte a formula eredményét az order metaadatokkal,
-   és túl korán aggregált vagy explodált.

A te új modelledben:

-   a formula eredménye → RawCut / RawKit
-   a példányok → ItemNeed
-   a rendelési tétel → OrderItemNeed
-   a teljes rendelés → OrderNeed

Ez tiszta, rétegezett, auditálható.

------------------------------------------------------------------------

🧩 3. A NeedCalculator új szerepe

A NeedCalculator eddig:

-   végigment a detaileken,
-   explode-olt,
-   aggregált,
-   externalRef-eket generált,
-   handlerSide-ot másolt,
-   ownerName-t másolt,
-   stb.

Ez túl sok felelősség volt.

Az új modellben:

✔ NeedCalculator::calculate()

egy termék egy példányára számol.

Ennyi.

Nem aggregál.
Nem explode-ol.
Nem generál externalRef-et.
Nem foglalkozik qty-vel.
Nem foglalkozik orderItemId-vel.

Csak:

-   végigmegy a detaileken,
-   ha cutting → RawCut
-   ha kitting → RawKit
-   és visszaad egy ItemNeed-et.

Pont.

------------------------------------------------------------------------

🔧 4. A calculate() implementációja (ahogy te mondtad)

Ez lesz a mag:

    ItemNeed NeedCalculator::calculate(const OrderLine& line) {
        ItemNeed need;

        for (auto& detail : detailsFor(line.productId, modeName)) {
            if (detail.kind == Cutting) {
                auto rc = evalFormulaCut(line, detail);
                need.cutPieces.append(rc);
            }
            else if (detail.kind == Kitting) {
                auto rk = evalFormulaKit(line, detail);
                need.kitItems.append(rk);
            }
        }

        return need;
    }

Ez tiszta, szép, egyszerű, tesztelhető.

🧩 6. Hol keletkeznek a példányok?

Az OrderItemNeed építésekor:

    OrderItemNeed buildOrderItemNeed(const OrderLine& line) {
        OrderItemNeed o;
        o.orderItemId = line.externalId;
        o.qty = line.qty;

        for (int i = 1; i <= line.qty; ++i) {
            ItemNeed need = NeedCalculator::calculate(line);
            o.itemNeeds.append(need);
        }

        return o;
    }

Itt lehet:

-   productInstanceId = “1234.1.A”
-   vagy “1234.1.1”
-   vagy amit akarsz
