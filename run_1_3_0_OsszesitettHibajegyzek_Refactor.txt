
🌟 TERMÉKTÍPUS‑LÉTREHOZÓ DIALÓGUS — TELJES TERV

0. Célok (UX + architektúra)

-   A user ne kapjon automatikus „szülő + új” nevet.
-   A user adja meg a nevet létrehozáskor.
-   A barcode automatikusan generálódjon, de a user később átírhatja.
-   A dialógus legyen kicsi, gyors, fókuszált, mint a ModeNameDialog.
-   Inline validáció: üres név, whitespace, duplikált név.
-   A ProductTreeManager workflow‑ja maradjon tiszta.
-   A ProductRegistry validációi változatlanul működjenek.
-   A barcode‑validáció továbbra is a BarcodeValidator feladata.

🌟 3. Barcode generálás új workflow

3.1. Root esetén

    base = slugFromName(name)
    barcode = ensureUnique(base)

3.2. Child esetén

    base = parent->barcode.isEmpty()
           ? slugFromName(name)
           : parent->barcode

    barcode = ensureUnique(base)

3.3. ensureUnique()

A te verziód tökéletes, csak az exists() helyett:

    if (BarcodeRegistry::instance().isBarcodeUnique(base))
        return base;

🌟 4. Barcode átírhatósága

A user továbbra is átírhatja a barcode‑ot a TreeView‑ban.

A BarcodeValidator:

-   ellenőrzi a prefixet (ha kell),
-   ellenőrzi az ütközést,
-   rollbackel, ha hibás.

Ez a dialógustól függetlenül működik.

🌟 5. ProductRegistry validációk

-   validateDomain() → name + barcode kötelező
-   validateDuplicate() → név + parentId egyedi

-   persist() → CSV mentés

Ez tökéletesen kompatibilis a dialógussal.

# 🌟 **CONTEXT SNAPSHOT (projektállapot-lenyomat)**

## **1) A feladat lényege**
Egy új **Terméktípus létrehozó dialógus** bevezetése a BOM Workbench bal oldali termékfájába, amely:

- a usertől **bekéri a nevet**,
- automatikusan generál **barcode‑ot** (hierarchikus számozással),
- inline validációt végez (üres név, duplikált név),
- a ProductTreeManager workflow‑jába illeszkedik,
- kompatibilis a ProductRegistry és BarcodeRegistry invariánsaival,
- UX‑ben a ModeNameDialog mintáját követi.

---

## **2) A jelenlegi rendszer működése**
- A ProductTreePresenter toolbarján két gomb van:
  - „Új termékcsoport” → addRootProduct()
  - „Új terméktípus” → addChildProduct()
- A ProductTreeManager jelenleg automatikus nevet és barcode‑ot generál.
- A user ezeket **mindig átírja**, ami UX‑szempontból felesleges.
- A barcode átírása a TreeView‑ban működik, a BarcodeValidator ellenőrzi.

---

## **3) A cél workflow**
### **Root létrehozás**
1. Dialógus → név bekérése
2. slugFromName(name)
3. ensureUnique(base)
4. ProductRegistry::insert()

### **Child létrehozás**
1. Szülő lekérése
2. Dialógus → név bekérése
3. base = parent->barcode vagy slugFromName(name)
4. ensureUnique(base)
5. ProductRegistry::insert()

---

## **4) A dialógus követelményei**
- QDialog alapú
- QLineEdit + OK/Cancel
- Inline validáció
- DuplicateCheck callback
- CursorAwarePlacement
- AttentionBlinker
- Shake animáció hibánál
- A barcode NEM része a dialógusnak

---

## **5) A barcode generálás új szabályai**
### **Root:**
```
base = slugFromName(name)
barcode = ensureUnique(base)
```

### **Child:**
```
base = parent->barcode.isEmpty()
       ? slugFromName(name)
       : parent->barcode

barcode = ensureUnique(base)
```

### **ensureUnique(base):**
- Ha base egyedi → visszaadja
- Ha nem → számozás:
  ```
  base-1
  base-2
  base-3
  ```

---

## **6) A validációs rétegek**
### **ProductRegistry**
- name kötelező
- barcode kötelező
- name + parentId egyedi

### **BarcodeRegistry**
- ledger modell
- isBarcodeUnique()
- barcodesWithPrefix()

### **BarcodeValidator**
- UI‑validáció barcode átíráskor
