# ⭐ CRUD Toolbar Factory – a végleges, architekturális terv

A cél:

- **egységes CRUD toolbar viselkedés**
- **Presenter‑szintű építés**
- **Workbench‑szintű névadás**
- **registry‑függő overlay támogatás**
- **akciók automatikus bekötése**
- **minimális duplikáció**
- **maximális bővíthetőség**

A Factory NEM a Workbench része.
A Factory NEM a View része.
A Factory a **Presenter infrastruktúra** része.

---

# ⭐ 1) A Factory API-ja (amit a Presenter hív)

A Presenter így fogja használni:

```cpp
_itemToolbar = CrudToolbarFactory::create({
    .parent = parent,
    .registry = _itemRegistry,
    .view = _itemView,
    .actions = {
        CrudAction::Add,
        CrudAction::Delete
    },
    .callbacks = {
        .onAdd = [this]() { addItem(); },
        .onDelete = [this]() { deleteItem(); }
    },
    .overlay = CrudOverlay::Enabled
});
```

Ez a BOM‑ban és az Order modulban is **1:1 működik**.

# ⭐ 2) A Factory paraméterstruktúrája

```cpp
struct CrudToolbarConfig {
    QWidget* parent;
    AbstractRegistry* registry;
    QWidget* view;

    std::vector<CrudAction> actions;

    struct {
        std::function<void()> onAdd;
        std::function<void()> onDelete;
        std::function<void()> onRename;
        std::function<void()> onClone;
        std::function<void()> onMoveUp;
        std::function<void()> onMoveDown;
    } callbacks;

    CrudOverlay overlay = CrudOverlay::None;
};
```

---

# ⭐ 3) A Factory visszatérési értéke

```cpp
QToolBar* CrudToolbarFactory::create(const CrudToolbarConfig& cfg);
```

A Factory:

- létrehozza a toolbar‑t
- hozzáadja az akciókat
- beköti a callbackeket
- ha kell, overlayt tesz rá
- registry‑hez köti az enable/disable logikát
- visszaadja a kész toolbar‑t

A Workbench majd:

```cpp
toolbar->setObjectName("order_item_toolbar");
```

# ⭐ 4) A Factory belső működése

### 4.1 Toolbar létrehozása

```cpp
auto* tb = new QToolBar("CRUD Toolbar", cfg.parent);
```

### 4.2 Overlay (ha kell)

```cpp
if (cfg.overlay == CrudOverlay::Enabled) {
    auto* ov = new RepositoryOverlayWidget(cfg.registry, tb, "CrudOverlay");
}
```

### 4.3 Akciók hozzáadása

```cpp
for (auto action : cfg.actions) {
    switch (action) {
        case CrudAction::Add:
            addAct = tb->addAction("➕ Új");
            QObject::connect(addAct, &QAction::triggered, cfg.callbacks.onAdd);
            break;
        case CrudAction::Delete:
            delAct = tb->addAction("🗑️ Törlés");
            QObject::connect(delAct, &QAction::triggered, cfg.callbacks.onDelete);
            break;
        case CrudAction::Rename:
            renAct = tb->addAction("✏️ Átnevezés");
            QObject::connect(renAct, &QAction::triggered, cfg.callbacks.onRename);
            break;
        // stb.
    }
}
```

### 4.4 Registry‑függő enable/disable

```cpp
QObject::connect(cfg.registry, &AbstractRegistry::selectionChanged,
                 tb, [=]() {
                     bool hasSelection = cfg.registry->hasSelection();
                     if (delAct) delAct->setEnabled(hasSelection);
                     if (renAct) renAct->setEnabled(hasSelection);
                 });
```

# ⭐ 5) Miért tökéletes ez a design?

## ✔ Presenter‑szintű
A CRUD toolbar domain‑logikát hordoz → Presenter felelősség.

## ✔ Workbench‑szintű névadás
A snapshot namespace Workbench‑szintű → Workbench adja a nevet.

## ✔ Overlay támogatás
A registry overlay Presenter‑szintű → Factory kezeli.

## ✔ Egységes ikonok, akciók, logika
A BOM és az Order modul végre **ugyanazt a mintát** használja.

## ✔ Minimális duplikáció
A BOM három toolbarja és az Order item toolbarja **ugyanarra a Factory‑ra épülhet**.

## ✔ Jövőálló
Ha holnap új CRUD modul jön → csak a Presenter hívja a Factory‑t.
