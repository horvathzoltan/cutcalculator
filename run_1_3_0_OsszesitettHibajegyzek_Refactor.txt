Oké, most már nagyon szépen kirajzolódik, hogy a roletta‑teszt csak az
első lépcső volt: egy darab OrderLine → egy darab ItemNeed. Most ezt
kell „felhúzni” order– és worksheet–szintre, úgy, hogy közben ne
borítsuk fel a már működő NeedCalculator::calculate logikát.

Az alábbi terv kifejezetten a mostani kódbázisra (NeedCalculator,
RawCut/RawKit, ItemNeed, OrderNeed, Cut/Kit aggregator skeletonok) épít.

------------------------------------------------------------------------

1. Cél és scope

Cél:
Egy teljes order (több order line, darabszámmal) anyagszükségletét:

-   példány szinten (minden fizikai termék külön ItemNeed),
-   majd worksheet szinten aggregálva (cutting + kitting lista)

le tudjuk kérni, és erre legyen egy roletta‑alapú order teszt, a mostani
roletta_calculation_tester mintájára.

------------------------------------------------------------------------

2. Fogalmi modell – order és need

2.1 Order és order line

Order:

-   orderId: QUuid
-   lines: QVector<OrderLineEx> (lásd lent)

OrderLineEx (order item):

-   orderItemId: QUuid
-   line: meglévő OrderLine (productId, w, h, handlerSide, externalId,
    ownerName, colorName)
-   qty: int – hány teljesen azonos példány tartozik ehhez a sorhoz
-   modeName: QString – melyik NeedCalculation módot használjuk (pl.
    “standard”, “roletta-default”)

2.2 Need szintek

-   ItemNeed – már létezik: egy fizikai példány (egy darab roletta) nem
    aggregált RawCut + RawKit listája.
-   OrderItemNeed – már létezik: egy order item összes példánya:
    -   orderItemId
    -   QVector<ItemNeed> itemNeeds – méret = qty, minden példány külön.
-   OrderNeed – már létezik: egy teljes order:
    -   orderId
    -   QVector<OrderItemNeed> orderItemNeeds.

------------------------------------------------------------------------

3. Rendszer viselkedés – OrderNeed építése

3.1 OrderNeedBuilder szolgáltatás

Új service osztály:

    // calculation/service/order_need_builder.h/.cpp

    struct OrderItem {
        QUuid orderItemId;
        OrderLine line;
        int qty;
        QString modeName;
    };

    struct Order {
        QUuid orderId;
        QVector<OrderItem> items;
    };

    class OrderNeedBuilder {
    public:
        static OrderNeed build(const Order& order, bool debug = false);
    };

Viselkedés:

1.  Input: Order (orderId + items).
2.  Minden OrderItem esetén:
    -   létrehoz egy OrderItemNeed‑et,
    -   itemNeeds.reserve(qty),
    -   for i in [1..qty]:
        -   meghívja:
            ItemNeed n = NeedCalculator::calculate(orderItem.line, orderItem.modeName, debug);
        -   orderItemNeed.itemNeeds.append(n);
3.  Az összes OrderItemNeed bekerül az OrderNeed.orderItemNeeds‑be.
4.  Output: OrderNeed.

Fontos:
A példányonkénti külön ItemNeed biztosítja, hogy később, ha kell, akár
példány‑szintű metaadatot is tudunk tárolni (pl. externalRef
kiterjesztése, sorszámozás stb.), de most még nem bonyolítjuk.

------------------------------------------------------------------------

4. Worksheet szintű aggregáció (cutting + kitting)

Itt lépnek képbe a már meglévő, de kikommentezett aggregátorok.

4.1 WorksheetNeed modell

Új, egyszerű modell:

    struct WorksheetNeed {
        QUuid worksheetId; // pl. egy munkalap azonosítója
        QVector<CutAggregatedItem> cuts;
        QVector<KitAggregatedItem> kits;
    };

4.2 OrderNeed → WorksheetNeed

Új service:

    // calculation/service/worksheet_builder.h/.cpp

    class WorksheetBuilder {
    public:
        static WorksheetNeed fromOrderNeed(const OrderNeed& orderNeed);
    };

Cutting:

1.  Végigmegyünk az orderNeed.orderItemNeeds összes ItemNeed elemén.
2.  Minden RawCut‑ból Piece objektumot készítünk (itt használjuk a
    meglévő Piece structot):
    -   materialBarcode = rawCut.materialBarcode
    -   requiredLength = rawCut.requiredLength
    -   handlerSide = line.handlerSide (ehhez az OrderLine‑t is át kell
        tudni érni → lásd 4.3)
    -   externalRef, ownerName, colorName, fullWidth, fullHeight
        kitöltése.
3.  Az összes Piece megy a CutAggregator::aggregate(pieces) függvénybe.
4.  Eredmény: QVector<CutAggregatedItem> → WorksheetNeed.cuts.

Kitting:

1.  Végigmegyünk az összes RawKit‑en.
2.  Mindenből KitItem:
    -   materialId opcionális (ha kell, MaterialRegistry‑ből
        visszakereshető),
    -   materialBarcode = rawKit.materialBarcode,
    -   quantity = rawKit.qty,
    -   ownerName, colorName, fullWidth, fullHeight a hozzá tartozó
        OrderLine‑ból.
3.  Az összes KitItem megy a KitAggregator::aggregate(items) függvénybe.
4.  Eredmény: QVector<KitAggregatedItem> → WorksheetNeed.kits.

4.3 OrderLine elérése aggregáláskor

Ahhoz, hogy a Piece/KitItem mezőit (ownerName, colorName, fullWidth,
fullHeight, handlerSide, externalRef) ki tudjuk tölteni, az
OrderNeed‑ben valahogy vissza kell tudni jutni az eredeti OrderLine‑hoz.

Egyszerű megoldás:

-   OrderItemNeed bővítése:

    struct OrderItemNeed {
        QUuid orderItemId;
        OrderLine line;              // új mező: az eredeti OrderLine
        QVector<ItemNeed> itemNeeds; // minden példány külön
    };

-   Az OrderNeedBuilder::build kitölti ezt a line mezőt.
-   A WorksheetBuilder pedig az OrderItemNeed.line‑ból veszi a
    metaadatokat.

5. Teszt forgatókönyv – roletta order

Új teszt: test/calculation/order_need_builder_tester.cpp (már szerepel a
pro‑ban, tehát ide illeszkedünk).

Teszt case vázlat:

1.  Testdata:
    -   products.csv, needrules.csv, need_calculation*.csv,
        materials.csv már léteznek a roletta teszthez.
    -   Létrehozunk egy Order‑t:
        -   orderId = QUuid::createUuid()
        -   2–3 OrderItem:
            -   pl. 2 db azonos rugós roletta (ugyanaz a méret,
                handlerSide, szín),
            -   1 db másik méretű roletta.
2.  OrderNeedBuilder::build(order):
    -   Ellenőrizzük:
        -   orderNeed.orderItemNeeds.size() megfelelő,
        -   minden OrderItemNeed.itemNeeds.size() == qty.
3.  WorksheetBuilder::fromOrderNeed(orderNeed):
    -   Ellenőrizzük:
        -   cuts és kits nem üresek,
        -   az aggregáció működik: az azonos anyag+méret+handlerSide
            kombinációk összeadódnak (cut),
        -   az azonos anyagok mennyisége összeadódik (kit).
4.  Roletta‑specifikus ellenőrzések:
    -   pl. egy adott tengely (TE-R-23) vágási hossza és darabszáma a
        várt érték.

7. Implementációs terv (pontonként végrehajtható)

1.  Order modell kiterjesztése
    -   Hozz létre calculation/service/order_need_builder.h/.cpp
        fájlokat.
    -   Definiáld az OrderItem és Order structokat (lásd 3.1).
    -   Bővítsd az OrderItemNeed structot a line mezővel
        (need_calculator.h).
2.  OrderNeedBuilder::build implementálása
    -   Input: const Order& order, bool debug.
    -   Végigiterál az order.items‑en.
    -   Minden itemre:
        -   létrehoz OrderItemNeed‑et (orderItemId, line),
        -   for i in [1..qty]:
            -   ItemNeed n = NeedCalculator::calculate(item.line, item.modeName, debug);
            -   itemNeed.itemNeeds.append(n);
    -   Összeállítja az OrderNeed‑et és visszaadja.
3.  CutAggregator és KitAggregator visszaélesztése
    -   Vedd ki a kommenteket a cut_aggregator.h/.cpp és
        kit_aggregator.h/.cpp fájlokból.
    -   Ellenőrizd, hogy a pro‑ban (QT project file) már benne vannak
        (benne vannak).
    -   Fordítsd le, javítsd az esetleges include hibákat.
4.  WorksheetNeed és WorksheetBuilder
    -   Hozz létre calculation/service/worksheet_builder.h/.cpp
        fájlokat.
    -   Definiáld a WorksheetNeed structot.
    -   Implementáld a WorksheetBuilder::fromOrderNeed függvényt:
        -   Gyűjtsd össze az összes RawCut → Piece (OrderItemNeed.line
            alapján).
        -   Gyűjtsd össze az összes RawKit → KitItem.
        -   Hívd meg a CutAggregator::aggregate és
            KitAggregator::aggregate függvényeket.
        -   Töltsd ki a WorksheetNeed.cuts és WorksheetNeed.kits
            mezőket.
5.  Roletta‑order teszt adat előkészítése
    -   A meglévő roletta tesztadatokra támaszkodva (products.csv,
        needrules.csv, materials, need_calculation*).
    -   A test/common/test_data_builder‑ben (vagy új helperben) készíts
        egy Order példányt:
        -   2–3 OrderItem rolettára, különböző méretekkel, qty‑vel.
6.  OrderNeedBuilder teszt
    -   A test/calculation/order_need_builder_tester.cpp‑ben:
        -   Betöltöd a registry‑ket (ahogy a többi teszt is teszi).
        -   Meghívod az OrderNeedBuilder::build(order) függvényt.
        -   Ellenőrzöd:
            -   orderNeed.orderItemNeeds.size() == várt érték.
            -   Minden OrderItemNeed.itemNeeds.size() == OrderItem.qty.
            -   Legalább egy ItemNeed tartalmaz cutItems és/vagy
                kitItems elemeket.
7.  WorksheetBuilder teszt
    -   Ugyanebben vagy külön tesztben:
        -   WorksheetNeed ws = WorksheetBuilder::fromOrderNeed(orderNeed);
        -   Ellenőrzöd:
            -   ws.cuts nem üres.
            -   ws.kits nem üres (ha van kitting formula).
            -   Az aggregáció működik: az azonos
                materialBarcode + requiredLength + handlerSide
                kombinációk darabszáma összeadódik.
8.  Logok és debug
    -   Szükség esetén adj hozzá zInfo logokat az OrderNeedBuilder és
        WorksheetBuilder kritikus pontjaira (orderId, orderItemId,
        counts).
    -   A tesztben futtass egy debug = true variánst is, hogy a formula
        engine debug dumpja látható legyen, ha kell.
9.  Refaktor és dokumentálás
    -   Ha a pipeline stabil:
        -   röviden dokumentáld a run_4_Order.txt vagy egy új
            run_4_OrderNeed.txt fájlban az order → orderNeed →
            worksheetNeed folyamatot.
        -   vedd fel az új fájlokat a files.txt listába is.
