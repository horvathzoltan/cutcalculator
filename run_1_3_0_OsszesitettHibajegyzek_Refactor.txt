Zoltán, ez most az a pont, ahol a FormulaEngine DSL‑ből valódi nyelvvé
válhat.
A dual‑syntax (operátor + függvény) choose/opt integrációja pontosan az
a lépés, amitől a motorod:

-   egységes lesz,
-   AST‑szinten működik,
-   nem kell hozzá külön mini‑interpreter,
-   és a teljes DSL bekerül a végrehajtási fába.

Amit most kapsz, az a teljes, lépésről‑lépésre végrehajtható terv,
minden komponenssel, minden szükséges módosítással, tisztán és
átláthatóan.

------------------------------------------------------------------------

⭐ A DUAL‑SYNTAX CHOOSE/OPT AST INTEGRÁCIÓ TELJES TERVE

(A FormulaEngine következő evolúciós szintje)

A cél:

-   A choose és opt AST node legyen.
-   A choose és opt Expression‑függvényként is működjön.
-   A choose és opt operátor‑szintaxisa is működjön.
-   A FormulaEngine::eval() ne tartalmazzon külön choose/opt ágakat.
-   A DSL minden eleme ugyanabba a végrehajtási fába kerüljön.

------------------------------------------------------------------------

⭐ 1. LÉPÉS – Tokenizer bővítése (DSL kulcsszavak felismerése)

A Tokenizer jelenleg csak operátorokat és az Expression‑függvényeket
ismeri.

Most hozzáadjuk:

-   choose
-   opt
-   qty
-   fixed
-   perOrder
-   perArea

Ezeket Identifier tokenként ismerjük fel, de fontos, hogy a Tokenizer ne
törje szét a choose: vagy opt: mintákat.

Tokenizer módosítás:

-   Ha egy identifier után : jön → külön token legyen:
    -   choose
    -   :
    -   opt
    -   :
    -   stb.

Ez kell ahhoz, hogy a Parser felismerje a DSL‑szintaxist.

------------------------------------------------------------------------

⭐ 2. LÉPÉS – Parser bővítése (DSL operátorok felismerése)

A Parser jelenleg:

-   infix operátorokat kezel (+ - * / > < ==)
-   függvényhívásokat kezel (avg(…))

Most hozzáadjuk:

✔ choose operátor felismerése

A Parser‑ben be kell tenni egy új precedenciát:

    cond ? A : B

Ez egy ternary operátor.

A Parser‑ben:

-   amikor ? token jön → új AST node: AstChoose
-   a : token a false‑ág kezdete

✔ opt operátor felismerése

A DSL‑szintaxis:

    opt:flag:+value

Ezt a Parser‑ben így kezeljük:

-   opt → függvényhívás neve
-   : → argumentum elválasztó
-   flag → első argumentum
-   : → második elválasztó
-   value → második argumentum

Parser‑szinten ez:

    opt(flag, value)

------------------------------------------------------------------------

⭐ 3. LÉPÉS – Új AST node‑ok

✔ AstChoose

    struct AstChoose : AstNode {
        AstNode* cond;
        AstNode* trueExpr;
        AstNode* falseExpr;
    };

✔ AstOpt

    struct AstOpt : AstNode {
        AstNode* flagExpr;
        AstNode* valueExpr;
    };

✔ AstQty (opcionális)

Ha a qty DSL‑t is be akarod emelni:

    qty:fixed:2
    qty:perArea:10000

→ AstQtyFixed, AstQtyPerArea, stb.

------------------------------------------------------------------------

⭐ 4. LÉPÉS – AstToExpression bővítése

Itt történik a DSL → Expression konverzió.

✔ choose → Expression ternary vagy függvény

Két lehetőség:

A) Expression ternary:

    cond ? trueExpr : falseExpr

B) Expression függvény:

    choose(cond, trueExpr, falseExpr)

Mindkettő működik.

✔ opt → Expression függvény

    opt(flagExpr, valueExpr)

------------------------------------------------------------------------

⭐ 5. LÉPÉS – Expression motor bővítése

A choose és opt Expression‑szintű függvény lesz.

✔ choose(cond, A, B)

    if (cond != 0) return A;
    else return B;

✔ opt(flag, value)

    if (flag == true) return value;
    else return 0;

Ez a jelenlegi DSL‑eddel 100% kompatibilis.

------------------------------------------------------------------------

⭐ 6. LÉPÉS – FormulaEngine::eval() egyszerűsítése

A jelenlegi:

-   külön ág choose‑ra
-   külön ág opt‑ra
-   külön ág qty‑ra

A dual‑syntax AST után:

✔ Minden DSL elem Expression‑ként fut

A FormulaEngine::eval() így néz ki:

    1) normalize
    2) multiline
    3) assignment
    4) string literal
    5) Expression pipeline

És kész.

Nem kell:

-   evalChoose()
-   evalWithOpt()
-   qty: ágak

Mert mind bekerül az AST‑be.

------------------------------------------------------------------------

⭐ 7. LÉPÉS – Dual‑syntax működés

A felhasználó írhatja:

Operátor-szerű:

    choose: w>1000 ? A : B
    opt:premium:+(w/10)

Függvény-szerű:

    choose(w>1000, A, B)
    opt(premium, w/10)

Mindkettő ugyanarra az AST‑re fordul.

------------------------------------------------------------------------

⭐ 8. LÉPÉS – Tesztek

A pipeline‑testerhez hozzáadjuk:

-   choose(cond, A, B)
-   opt(flag, value)
-   nested choose függvény-szintaxissal
-   nested opt függvény-szintaxissal
-   assignment + choose függvény-szintaxissal
-   assignment + opt függvény-szintaxissal

------------------------------------------------------------------------

⭐ Összegzés

A dual‑syntax choose/opt AST integráció:

-   egységesíti a DSL‑t
-   megszünteti a külön mini‑interpretereket
-   a teljes nyelvet Expression‑szintre emeli
-   egyszerűbbé teszi a FormulaEngine‑t
-   sokkal könnyebb lesz bővíteni
-   sokkal kevesebb hibalehetőséget tartalmaz

Ez a FormulaEngine „2.0” alapja.

------------------------------------------------------------------------

⭐ IMPLEMENTÁCIÓS TERV

Cél: általános kifejezéskezelés a FormulaEngine-ben, minden DSL → függvény formára fordítva

1) A FormulaEngine NEM számol többé.

Csak fordít:

    DSL → Expression string → Expression::Parse() → Expression::Calculate()

2) A DSL fordító (dslToExpression) a kulcs.

Ez fogja felismerni:

-   w-10 → sub(w,10)
-   h-15 → sub(h,15)
-   w*h → mul(w,h)
-   (w*h)/1000 → div(mul(w,h),1000)
-   qty:fixed:3 → mul(qty,3)
-   choose: → if(...)
-   opt: → ignorálás vagy későbbi flag-kezelés

3) Általános aritmetikai kifejezések támogatása

Ehhez kell:

-   tokenizáló (változó, literál, operátor, zárójel)
-   shunting-yard (precedencia + zárójelek)
-   AST építés
-   AST → Expression string fordító

Ez a rész lesz a „motor”.

4) A choose: operátor Expression formára fordítása

Példa:

    choose: (w*h > 1000000) ? A : B
    → if(gt(mul(w,h),1000000), A, B)

5) Az opt: részek leválasztása

A fő kifejezés:

    h-10 + opt:paint:+40
    → h-10

A többi ignorálható, amíg nincs flag-kezelés.

6) A FormulaEngine::eval() végül így néz ki:

    QString expr = dslToExpression(f);
    Expression e = Expression::Parse(expr);
    QVariant v = e.Calculate();

⭐ TOKEN SNAPSHOT

(ez a „hogyan fog kinézni a tokenizálás” jegyzet)

A tokenizáló feladata:

Bemenet:

    (w-10) * (h-20) / 1000

Tokenek:

    [
      "(", "w", "-", "10", ")",
      "*",
      "(", "h", "-", "20", ")",
      "/",
      "1000"
    ]

Token típusok:

-   Identifier: w, h, qty, A, B
-   Number: 10, 20, 1000, 1e6, 5.5
-   Operator: +, -, *, /, >, <, >=, <=, ==
-   Paren: (, )
-   Keyword: opt:, choose:, len:, qty:fixed:, stb. (külön kezelve)
-   Whitespace: ignorálva

Operátorprecedencia:

1.  *, /
2.  +, -
3.  összehasonlítók: >, <, >=, <=, ==

Shunting-yard output (postfix):

    w 10 - h 20 - * 1000 /

AST:

            div
           /    \
         mul    1000
        /   \
     sub     sub
    /   \   /   \
    w   10 h    20

Expression string:

    div(
        mul(
            sub(w,10),
            sub(h,20)
        ),
        1000
    )

És ezt már tudja a meglévő Expression rendszer.

Patch terv – FormulaEngine átalakítása változó‑alapú működésre

Alapelv:
FormulaEngine ezentúl csak kifejezést kap (QString expr), minden input
és output a VariableRegistry‑n keresztül megy.

------------------------------------------------------------------------

1. FormulaEngine API átalakítása

Most:

    static EvaluatedFormula eval(const QString& f, int w, int h, int qty);

Lesz:

    static EvaluatedFormula eval(const QString& f);

Teendők

-   Minden eval(..., w, h, qty) hívást átírni úgy, hogy:
    -   a hívás előtt a VariableRepository‑be bekerüljenek:
        -   w, h, qty (és később bármi más: margin, area, stb.)
    -   a FormulaEngine::eval(f) már nem kapja meg ezeket paraméterként.

------------------------------------------------------------------------

2. evalExpressionGeneric átalakítása

Most:

    static QVariant evalExpressionGeneric(const QString& expr, int w, int h, int qty)
    {
        auto& vars = VariableRepository::instance();
        vars.set("w",   w);
        vars.set("h",   h);
        vars.set("qty", qty);
        ...
    }

Lesz:

    static QVariant evalExpressionGeneric(const QString& expr)
    {
        auto& vars = VariableRepository::instance();
        // itt már NEM állítunk be semmit, csak olvasunk
        ...
    }

Teendők

-   Kivenni a w/h/qty beállítását innen.
-   Mindenhol, ahol eddig evalExpressionGeneric(t, w, h, qty) volt,
    átírni evalExpressionGeneric(t)‑re.
-   Biztosítani, hogy a hívó fél már előtte feltöltötte a registry‑t.

------------------------------------------------------------------------

3. FormulaEngine::eval belső logika módosítása

Most:

    EvaluatedFormula FormulaEngine::eval(const QString& f, int w, int h, int qty)
    {
        ...
        // qty: DSL-ek w,h,qty alapján
        // choose: evalChoose(t, w, h, qty)
        // opt: evalWithOpt(t, w, h, qty)
        // általános kifejezés: evalExpressionGeneric(t, w, h, qty)
    }

Lesz:

    EvaluatedFormula FormulaEngine::eval(const QString& f)
    {
        EvaluatedFormula out;
        out.stringValue.clear();

        QString t = FormulaNormalizer::normalizeWhitespace(f);
        t = FormulaNormalizer::stripOuterParens(t);

        // szám literálok (ugyanaz maradhat)
        // qty: DSL-ek → VariableRepository-ből olvasott w,h,qty-vel számolnak
        // choose: → evalChoose(t)
        // opt: → evalWithOpt(t)
        // minden más → evalExpressionGeneric(t)

        return out;
    }

Teendők

-   Kivenni a w, h, qty paramétereket a függvény aláírásából és
    belsejéből.
-   A qty: DSL ágakban w és h értékét a VariableRepository‑ből
    kiolvasni:
    -   pl. vars.get("w").toInt() stb.
-   evalChoose és evalWithOpt aláírását is módosítani: csak
    const QString& t.

------------------------------------------------------------------------

4. evalChoose és evalWithOpt átalakítása

Most:

    EvaluatedFormula FormulaEngine::evalChoose(const QString& t, int w, int h, int qty);
    EvaluatedFormula FormulaEngine::evalWithOpt(const QString& t, int w, int h, int qty);

Lesz:

    EvaluatedFormula FormulaEngine::evalChoose(const QString& t);
    EvaluatedFormula FormulaEngine::evalWithOpt(const QString& t);

Belső változás

-   Ahol eddig eval(branch, w, h, qty) volt, ott most simán eval(branch)
    lesz.
-   A feltétel kiértékelése (condExpr) már így is az új pipeline‑on
    megy, csak a változókat most a registry‑ből veszi az Expression.

------------------------------------------------------------------------

5. VariableRepository használatának egységesítése

Teendők

-   Bevezetni egy konvenciót: minden FormulaEngine hívás előtt a hívó
    fél:
    -   törli vagy reseteli a releváns változókat (opcionális, ha kell),
    -   beállítja:
        -   w, h, qty,
        -   később: margin, extra, discount, stb.
-   A FormulaEngine soha többé nem állít be input változót, csak:
    -   olvas belőlük,
    -   és opcionálisan eredményt ír vissza (pl. result_length,
        result_pieces).

------------------------------------------------------------------------

6. area kezelésének előkészítése

Két lépésben:

6.1. Függvényként

-   Expression oldalon bevezetni egy area(a,b) függvényt:
    -   Function::area(double a, double b) { return a*b; }
-   A DSL‑ben használható lesz:
    -   area(w,h)/1000

6.2. Változóként (ha akarod)

-   A hívó fél (pl. NeedCalculator) induláskor:
    -   vars.set("area", w*h);
-   A formula:
    -   area / 1000

Első körben elég a függvényes verziót megcélozni.
