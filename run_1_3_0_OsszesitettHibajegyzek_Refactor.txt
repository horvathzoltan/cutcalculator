Nagyon szép, kerek a kép most — minden fontos fájl a kezünkben van.
Nézzük végig, mi van most, és utána lépésről lépésre megtervezzük a
Final placement after first stable frame stratégiát.

1. Jelenlegi viselkedés összefoglalása

MainWindow:

-   Konstruktorban:

        QTimer::singleShot(0, this, [this]() {
            bool restoredFromSnapshot = SnapshotManager::instance().restoreWindowSnapshot(this);
            if (!restoredFromSnapshot) { ... fallback LayoutDefaultStore ... }
            _windowRestoredOnce = true;
            GeometryHelper::restoreSplitterState(...);
        });

-   showEvent csak logol.

-   moveEvent:

    -   monitorprofilt logol (monitorProfileFor(this) →
        currentMonitorProfile()),
    -   ha
        _windowRestoredOnce && GeometryHelper::isWindowGeometryReady(this)
        → saveWindowSnapshot().

-   resizeEvent is ment snapshotot hasonló guarddal.

-   closeEvent menti a fallback percent‑based geometriát
    (LayoutDefaultStore).

SnapshotManager:

-   currentMonitorProfile(QWidget*):

    -   ha van window->screen() → azt használja,
    -   különben QGuiApplication::primaryScreen(),
    -   profil: "{width}x{height}_{dpi}dpi".

-   snapshotFilePathFor(window, access):

    -   currentMonitorProfile(window) alapján kér path‑ot a
        FileNameHelper‑től.

-   saveWindowSnapshot(window):

    -   path a jelenlegi monitorprofil alapján,
    -   GeometryHelper::saveWindowGeometry(window) → percent string,
    -   window->screen()->size() → audit screen,
    -   QSettings → Window/geometry, Window/screen.

-   restoreWindowSnapshot(window):

    -   path a jelenlegi monitorprofil alapján,
    -   ha létezik: Window/geometry, Window/screen,
    -   GeometryHelper::restoreWindowGeometry(window, geom, savedScreen).

GeometryHelper:

-   saveWindowGeometry:

    -   guard: visible + polished + screen,
    -   ha nem stabil → log + QTimer::singleShot(0, ...) újrapróbálás,
    -   percent‑based mentés (x%, y%, w%, h%) a window->screen()->size()
        alapján.

-   restoreWindowGeometry:

    -   guard: isGeometryReadyForRestore (visible, polished, min size),
    -   ha nem → log + QTimer::singleShot(0, ...) újrapróbálás,
    -   window->screen()->size() alapján számol vissza pixelt,
    -   setGeometry(x,y,w,h) + log.

2. A probléma lényege (Wayland + több monitor)

A logod tökéletesen mutatja:

    Monitor profile set: 1366x768_96dpi
    showEvent: ... VGA-1 (1366x768)
    Window geometry restored: ... (screen=1366x768)
    Window restored from geometry snapshot file: ...geometry_1366x768_96dpi.ini
    ...
    Monitor profile changed: 1366x768_96dpi → 1920x1080_96dpi
    Window geometry saved: ...
    Geometry snapshot saved to file: ...geometry_1920x1080_96dpi.ini

Tehát:

1.  A Qt szerint az ablak a bal oldali (VGA‑1, 1366×768) monitoron jön
    létre.
2.  A snapshot restore is ennek a profilnak a fájljából történik.
3.  A WM ezután átmozgatja az ablakot a nagy monitorra (1920×1080).
4.  A mentés már az új profilba történik.
5.  A kicsi monitor snapshotja sosem frissül, a nagy monitoré igen.
6.  A következő induláskor a restore rossz profilból indul.

És ami a csavar:

-   lehet olyan WM, ami nem mozgatja át → ilyenkor a korai restore
    helyes,
-   lehet olyan WM, ami átmozgatja → ilyenkor a korai restore rossz
    monitorprofilból dolgozik.

Ezért kell egy WM‑független, platformfüggetlen, determinisztikus
stratégia.

------------------------------------------------------------------------

3. Ipari minta: „Final placement after first stable frame”

A nagy rendszerek (Chromium, VSCode, Qt Creator, KDE appok) közös
mintája:

  A végleges monitorpozíciót csak akkor tekintjük érvényesnek, amikor az
  ablak már megjelent, és a WM befejezte az első elhelyezési ciklust.

Ez nálad így fordítható le:

1.  Korai restore: induláskor, a Qt által ismert első monitorprofil
    alapján.
2.  Megfigyelés: figyelni, hogy a monitorprofil megváltozik‑e az első
    stabil frame után.
3.  Döntés:
    -   ha nem változik → a korai restore a végleges,
    -   ha változik → a WM áthelyezte → újra kell restore‑olni a
        végleges profilból.
4.  Snapshot mentés: csak akkor, ha már végleges monitorprofil van.

Kulcs: nem időzítésre, hanem monitorprofil‑változásra építünk.

------------------------------------------------------------------------

4. Új állapotgép, amit bevezetünk

A MainWindow szintjén:

-   Új mező:

        bool _windowRestoredOnce = false;      // már most is van
        QString _initialMonitorProfile;        // új

-   Állapotok:

    1.  Initial: még nem restore‑oltunk → konstruktor.
    2.  EarlyRestored: korai restore lefutott, de nem tudjuk, hogy a WM
        át fogja‑e mozgatni.
    3.  FinalRestored: már tudjuk, hogy a monitorprofil végleges (WM
        vagy mozgatott, vagy nem), és a snapshot is a jó profilból van.

-   Szabályok:

    -   Snapshotot csak FinalRestored állapotban mentünk.
    -   Ha EarlyRestored állapotban monitorprofil változik → újra
        restore a végleges profilból → FinalRestored.
    -   Ha EarlyRestored állapotban nem változik a profil, de jön az
        első user‑move/resize → tekintjük véglegesnek → FinalRestored.

5. Konkrét viselkedés WM típusonként

5.1. WM átmozgatja az ablakot (Wayland KWin/Mutter/Sway, XWayland egyes esetek)

-   Konstruktor → korai restore a bal monitor profiljából.

-   showEvent → log, _initialMonitorProfile = monitorProfileFor(this).

-   WM átmozgatja → moveEvent fut, monitorProfileFor(this) ≠
    _initialMonitorProfile.

-   Ekkor:

    -   felismerjük: WM‑move történt,
    -   újra hívjuk restoreWindowSnapshot(this) → már az új profil
        fájljából,
    -   _windowRestoredOnce = true,
    -   innentől snapshot menthető.

5.2. WM nem mozgatja az ablakot (X11, minimal Wayland compositor)

-   Konstruktor → korai restore a valós monitorprofilból.

-   showEvent → _initialMonitorProfile = monitorProfileFor(this).

-   Nincs WM‑move → moveEvent első hívásakor
    current == _initialMonitorProfile.

-   Ekkor:

    -   felismerjük: nem történt WM‑move,
    -   a korai restore a végleges,
    -   _windowRestoredOnce = true,
    -   innentől snapshot menthető.

6.2. MainWindow: konstruktor átalakítása

Most a restore egy singleShot(0)‑ban van, és ott állítod
_windowRestoredOnce = true‑ra.
Ezt át kell alakítani úgy, hogy:

-   a korai restore megmarad,
-   de _windowRestoredOnce még ne legyen true,
-   és elmentsük az induló monitorprofilt.

Új logika:

    MainWindow::MainWindow(QWidget *parent)
        : QMainWindow(parent)
        , ui(new Ui::MainWindow)
    {
        ui->setupUi(this);
        initEventLogWidget();

        QTimer::singleShot(0, this, [this]() {
            // 0) induló monitorprofil elmentése
            _initialMonitorProfile = SnapshotManager::instance().monitorProfileFor(this);
            zInfo(QString("🖥️ Initial monitor profile: %1").arg(_initialMonitorProfile));

            // 1) Window restore snapshotból (per monitor profil)
            bool restoredFromSnapshot = SnapshotManager::instance().restoreWindowSnapshot(this);

            // 2) Ha nincs snapshot, fallback UiDefaultStore-ból
            if (!restoredFromSnapshot) {
                const QString geom = LayoutDefaultStore::instance().windowGeometryPercent();
                const QSize savedScreen = GeometryHelper::parseScreenSize(
                    LayoutDefaultStore::instance().screenSizeString());
                if (!geom.isEmpty()) {
                    GeometryHelper::restoreWindowGeometry(this, geom, savedScreen);
                }
            }

            // ⚠️ Itt MÉG NEM tesszük true-ra:
            // _windowRestoredOnce = true;

            // 3) MainWindow splitter állapot – fallback percent alapú
            const QString split = LayoutDefaultStore::instance().mainSplitterPercent();
            if (!split.isEmpty()) {
                GeometryHelper::restoreSplitterState(ui->splitter, split);
            }

            zInfo("✅ UI Settings loaded (percent-based + snapshot-aware)");
        });

        ...
    }

6.3. MainWindow: showEvent maradhat lognak

A showEvent most csak logol — ez jó, maradhat.
Nem kell ide logika, a döntés a moveEvent‑ben fog történni.

------------------------------------------------------------------------

6.4. MainWindow: moveEvent → WM‑move detektálás + final restore

Most:

-   monitorprofilt logolsz,
-   ha _windowRestoredOnce && isWindowGeometryReady → save snapshot.

Ezt át kell alakítani:

1.  Első fázis: ha még nem final restore történt (!_windowRestoredOnce):

    -   lekérjük az aktuális monitorprofilt,
    -   összehasonlítjuk _initialMonitorProfile‑lal,
    -   ha különbözik → WM‑move → újra restore a végleges profilból,
    -   ha ugyanaz → WM nem mozgatott → korai restore a végleges.

2.  Második fázis: ha már final restore (_windowRestoredOnce == true):

    -   ha GeometryHelper::isWindowGeometryReady(this) →
        saveWindowSnapshot(this).

Új moveEvent:

    void MainWindow::moveEvent(QMoveEvent* e) {
        QMainWindow::moveEvent(e);

        QString current = SnapshotManager::instance().monitorProfileFor(this);

        // 1) WM-move / final placement detektálás
        if (!_windowRestoredOnce) {
            if (_initialMonitorProfile.isEmpty()) {
                // Biztonsági fallback: ha valamiért nem állt be
                _initialMonitorProfile = current;
                zWarning(QString("⚠️ Initial monitor profile was empty, set to: %1").arg(current));
            }

            if (current != _initialMonitorProfile) {
                // 🖥️ WM áthelyezte az ablakot → végleges monitorprofil megérkezett
                zInfo(QString("🖥️ Monitor profile changed (WM move): %1 → %2")
                          .arg(_initialMonitorProfile, current));

                // Újra restore a VÉGLEGES profilból
                bool restored = SnapshotManager::instance().restoreWindowSnapshot(this);
                if (!restored) {
                    zWarning("⚠️ No snapshot for final monitor profile; keeping current geometry");
                }

                _windowRestoredOnce = true;
                return; // fontos: itt NEM mentünk snapshotot
            } else {
                // 🖥️ WM nem mozgatta át → a korai restore a végleges
                zInfo(QString("🖥️ Monitor profile unchanged (%1) → early restore is final")
                          .arg(current));
                _windowRestoredOnce = true;
                // és megyünk tovább a mentés logikára (user-move esetén)
            }
        }

        // 2) Ha már final restore történt → user-move esetén mentünk snapshotot
        if (_windowRestoredOnce && GeometryHelper::isWindowGeometryReady(this)) {
            SnapshotManager::instance().saveWindowSnapshot(this);
        }
    }

A monitorprofil‑logolást (set/changed) most már kiváltja ez a logika, de
ha szeretnéd, beépíthetjük a fenti logokba.

------------------------------------------------------------------------

6.5. MainWindow: resizeEvent / changeEvent

Ezek most:

    if (_windowRestoredOnce && GeometryHelper::isWindowGeometryReady(this)) {
        SnapshotManager::instance().saveWindowSnapshot(this);
    }

Ez jó, csak annyi a lényeg, hogy _windowRestoredOnce most már valóban
azt jelenti, hogy:

  „A végleges monitorprofilra már restore‑oltunk (vagy a korai restore
  volt a végleges).”

Tehát ezeket nem kell módosítani, csak az új szemantikával együtt
értelmezni.

6.6. SnapshotManager: log finomhangolás (opcionális)

A currentMonitorProfile és snapshotFilePathFor logikája jó.
Egyetlen dolgot érdemes még hozzátenni:

-   amikor restoreWindowSnapshot fut, logolhatjuk a monitorprofilt is:

    bool SnapshotManager::restoreWindowSnapshot(QWidget* window)
    {
        ...
        const QString profile = currentMonitorProfile(window);
        ...
        zInfo(QString("✅ Window restored from geometry snapshot file: %1 (profile=%2)")
                  .arg(path, profile));
        return true;
    }

Ez segít auditálni, hogy tényleg a jó profilból restore‑oltunk.

7. Implementációs / patching terv (konkrét lépések)

1.  MainWindow mezők bővítése

    -   mainwindow.h:

            bool _windowRestoredOnce = false;
            QString _initialMonitorProfile;

2.  Konstruktor módosítása

    -   A QTimer::singleShot(0, ...) blokkban:

        -   _initialMonitorProfile = SnapshotManager::instance().monitorProfileFor(this);
        -   _windowRestoredOnce beállítását törölni ebből a blokkól.
        -   A többi restore/fallback logika marad.

3.  showEvent változatlanul hagyása (csak log).

4.  moveEvent teljes újraírása a fenti algoritmus szerint

    -   WM‑move detektálás: current != _initialMonitorProfile.
    -   Ha WM‑move → újra restoreWindowSnapshot(this) →
        _windowRestoredOnce = true.
    -   Ha nem WM‑move → _windowRestoredOnce = true (korai restore a
        végleges).
    -   Snapshot mentés csak akkor, ha
        _windowRestoredOnce && isWindowGeometryReady.

5.  resizeEvent / changeEvent érintetlenül hagyása

    -   Ezek már most is _windowRestoredOnce‑re támaszkodnak → mostantól
        ez „final placement” jelző.

6.  SnapshotManager opcionális log finomhangolása

    -   restoreWindowSnapshot logjába beleírni a monitorprofilt is
        (audit).

7.  Tesztelési forgatókönyvek

    -   Wayland + több monitor, kurzor a nagy monitoron:

        -   Indítás → korai restore kicsi profilból.
        -   WM átmozgat → moveEvent → profilváltozás → újra restore nagy
            profilból.
        -   Mentés már a nagy profilba megy.
        -   Következő indítás → korai restore már a nagy profilból.

    -   Wayland + több monitor, kurzor a kicsin:

        -   Indítás → korai restore kicsi profilból.
        -   Nincs WM‑move → profil nem változik → korai restore a
            végleges.
        -   Mentés a kicsi profilba megy.

    -   X11 / nem mozgatós WM:

        -   Indítás → korai restore valós profilból.
        -   Profil nem változik → korai restore a végleges.
        -   Mentés ugyanabba a profilba.
