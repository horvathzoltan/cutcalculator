⭐ I. DSL bővítés: choose: operátor

🎯 Cél

Olyan formula támogatása, amely feltétel alapján két érték közül
választ:

    choose: (w*h > 5000000) ? MOTOR_A : MOTOR_B

A choose: operátor:

-   feltételt értékel ki (bal oldal > jobb oldal)
-   stringet ad vissza (pl. motor barcode)
-   a NeedCalculator ezt anyagként tudja értelmezni

------------------------------------------------------------------------

⭐ 1. FormulaEngine bővítése

1.1. Felismerés

A eval() elején:

    if (t.startsWith("choose:")) {
        return evalChoose(t, w, h, qty);
    }

1.2. evalChoose() működése

1.  Levágjuk a choose: prefixet.
2.  Megkeressük a ? és : pozícióját.
3.  A feltételt kivágjuk:
    pl. (w*h > 5000000)
4.  A feltételt szétszedjük összehasonlító operátor mentén:
    >, <, >=, <=, ==
5.  Mindkét oldalt külön átadjuk a FormulaEngine‑nek:
    -   w*h → szám
    -   5000000 → szám
6.  Kiértékeljük a feltételt.
7.  Ha igaz → visszaadjuk a bal oldali értéket (string)
8.  Ha hamis → visszaadjuk a jobb oldali értéket (string)

1.3. Visszatérési érték

A choose: nem ad vissza hossz/pieces értéket.
Ez egy string formula, amit a NeedCalculator értelmez.

Ezért:

    EvaluatedFormula out;
    out.length_mm = 0;
    out.pieces = 0;
    out.stringValue = "MOTOR_A";

Ha nincs stringValue meződ, most kell bevezetni.

------------------------------------------------------------------------

⭐ 2. Validáció bővítése

A isFormulaValid()-ben:

    if (trimmed.startsWith("choose:"))
        return validateChoose(trimmed);

A validateChoose():

-   ellenőrzi, hogy van ? és :
-   ellenőrzi, hogy a feltételben van összehasonlító operátor
-   a két oldal szintaktikailag értelmezhető (nem kell kiértékelni)
-   a két ág nem üres string

Nem kell mély validáció — a FormulaEngine úgyis elkapja a hibát.

------------------------------------------------------------------------

⭐ 3. Tesztek a FormulaEngineTester-ben

✔ 3.1. Egyszerű motorválasztás

    auto ev = FormulaEngine::eval("choose: (w*h > 5000000) ? A : B", 3000, 2000, 1);
    Q_ASSERT(ev.stringValue == "A");

✔ 3.2. Másik ág

    auto ev = FormulaEngine::eval("choose: (w*h > 5000000) ? A : B", 1000, 1000, 1);
    Q_ASSERT(ev.stringValue == "B");

✔ 3.3. Hibás feltétel

    auto ev = FormulaEngine::eval("choose: (w*h > ) ? A : B", 1000, 1000, 1);
    Q_ASSERT(ev.stringValue.isEmpty());

------------------------------------------------------------------------

⭐ II. DSL bővítés: opt: operátor

🎯 Cél

Feltételes hossz‑kiegészítés:

    h-15 + opt:paint:+40

A opt::

-   nem szám, hanem feltételes művelet
-   ha flag igaz → hozzáadja a +40‑et
-   ha flag hamis → kihagyja a műveletet

------------------------------------------------------------------------

⭐ 1. FormulaEngine bővítése

1.1. Felismerés

A eval() végén, a matematikai műveletek után:

    if (t.contains("opt:"))
        return evalWithOpt(t, w, h, qty, flags);

1.2. evalWithOpt() működése

1.  A kifejezést szétszedjük + mentén.
2.  Minden tokenre:
    -   ha opt:<flag>:+<value> →
        -   ha flag igaz → hozzáadjuk a value‑t
        -   ha flag hamis → kihagyjuk
    -   különben → átadjuk a FormulaEngine‑nek (pl. h-15)
3.  Összeadjuk az eredményeket.

1.3. Fontos

Az opt: nem kerül be a matematikai kifejezésbe.
Nem ad vissza 0‑át.
Nem okoz szorzási hibát.

------------------------------------------------------------------------

⭐ 2. Validáció bővítése

A isFormulaValid()-ben:

    if (trimmed.contains("opt:"))
        return validateOpt(trimmed);

A validateOpt():

-   ellenőrzi, hogy a token így néz ki:
    opt:<flag>:+<value>
-   <value> integer
-   <flag> nem üres

------------------------------------------------------------------------

⭐ 3. Tesztek a FormulaEngineTester-ben

✔ 3.1. Festés nélkül

    auto ev = FormulaEngine::eval("h-15 + opt:paint:+40", 1200, 1500, 1, { .paint = false });
    Q_ASSERT(ev.length_mm == 1500 - 15);

✔ 3.2. Festéssel

    auto ev = FormulaEngine::eval("h-15 + opt:paint:+40", 1200, 1500, 1, { .paint = true });
    Q_ASSERT(ev.length_mm == (1500 - 15 + 40));

✔ 3.3. Hibás opt

    auto ev = FormulaEngine::eval("h-15 + opt:paint:xx", 1200, 1500, 1);
    Q_ASSERT(ev.length_mm == 0);

------------------------------------------------------------------------

⭐ III. NeedCalculator integráció

A NeedCalculator:

-   ha a formula stringValue-t ad → azt anyag barcode‑ként kezeli
-   ha a formula length_mm-et ad → vágási hossz
-   ha pieces → darabszám

Ez már most is működik, csak a stringValue mezőt kell bevezetni.

⭐ PATCH TERV — DSL bővítés: choose: + opt:

P1 — EvaluatedFormula bővítése

Cél: legyen hely a string‑alapú eredménynek (motor barcode).

-   Adj hozzá egy mezőt:

    QString stringValue;

-   A FormulaEngine minden ágában alapértelmezés:

    out.stringValue.clear();

-   A choose: operátor ezt fogja kitölteni.

------------------------------------------------------------------------

P2 — FormulaEngine::eval() belépési pont bővítése

Cél: felismerni az új DSL prefixeket.

A eval() elején:

    if (t.startsWith("choose:"))
        return evalChoose(t, w, h, qty, flags);

    if (t.contains("opt:"))
        return evalWithOpt(t, w, h, qty, flags);

A flags a NeedCalculator‑tól jön (pl. .paint = true/false).

------------------------------------------------------------------------

⭐ CHOOSE IMPLEMENTÁCIÓ

P3 — evalChoose() létrehozása

Cél: ternary logika implementálása.

Lépések:

1.  Levágni a choose: prefixet.
2.  Megkeresni a ? és : pozícióját.
3.  Kivágni:
    -   feltétel
    -   true‑ág
    -   false‑ág
4.  A feltételt szétszedni összehasonlító operátor mentén:
    -   >, <, >=, <=, ==
5.  Mindkét oldalt külön átadni a FormulaEngine‑nek:
    -   eval("w*h") → szám
    -   eval("5000000") → szám
6.  Kiértékelni a feltételt.
7.  Ha igaz → out.stringValue = trueBranch
8.  Ha hamis → out.stringValue = falseBranch

Fontos:
A choose: NEM ad vissza length_mm‑et vagy pieces‑t.

------------------------------------------------------------------------

A isFormulaValid()-ben:

A validateChoose():

-   ellenőrzi, hogy van ? és :

-   a két ág nem üres

⭐ OPT IMPLEMENTÁCIÓ

P5 — evalWithOpt() létrehozása

⭐ NEEDCALCULATOR INTEGRÁCIÓ

P7 — NeedCalculator módosítása

Cél: a stringValue‑t anyagként kezelni.

Ha a formula eredménye:

-   stringValue nem üres →
    → ezt anyag barcode‑ként kell értelmezni
    → a NeedCalculator a megfelelő motor anyagot adja vissza

Ez már most is működik, csak a stringValue mezőt kell használni.
