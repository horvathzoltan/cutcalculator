✅ PATCH TERV – tömör, végrehajtható lépések

Ez a terv pontosan azt valósítja meg, amit szeretnél:

  A ternary (cond ? a : b) és optional (flag ? expr) zárójel nélkül
  működjön,
  de ha a true‑ágban vagy false‑ágban bármi összetettebb kifejezés van,
  akkor azt kötelező legyen zárójelezni.

A parsered ezt már 80%-ban tudja – most befejezzük.

------------------------------------------------------------------------

⭐ 1. Token bővítése: parenDepth

token.h → struct Token:

    int parenDepth = 0;

Ez kell ahhoz, hogy a parser tudja, melyik ? melyik zárójel‑szinthez
tartozik.

------------------------------------------------------------------------

⭐ 2. Tokenizer: minden tokenhez töltsd ki a parenDepth-et

tokenizer.cpp:

-   vezess be egy lokális változót:

    int parenDepth = 0;

-   amikor ( jön → parenDepth++
-   amikor ) jön → parenDepth--
-   minden token append-nél:

    tokens.append({type, text, 0, parenDepth});

(ha a struct sorrendje más, igazítsd hozzá)

------------------------------------------------------------------------

⭐ 3. Parser: saját parenDepth követése

parser.cpp → toRpn() elejére:

    int parenDepth = 0;

Majd:

-   LParen → parenDepth++
-   RParen → parenDepth--

És amikor tokennel dolgozol:

    t.parenDepth = parenDepth;

------------------------------------------------------------------------

⭐ 4. Nested ? tiltása zárójel nélkül

parser.cpp → a if (t.type == TokenType::Question) blokkban:

    if (!questionHasColon.isEmpty()) {
        if (parenDepth == 0) {
            return fail("Nested ternary/optional requires parentheses");
        }
    }

Ez megakadályozza:

-   ternary a ternary-ben
-   optional a ternary-ben
-   ternary az optional-ban
-   optional az optional-ban

zárójel nélkül.

------------------------------------------------------------------------

⭐ 5. : csak akkor engedélyezett, ha a hozzá tartozó ? ugyanabban a zárójel-szintben van

parser.cpp → a Colon kezelésénél:

1.  keresd meg a legfelső ?‑t az opStack-ben
2.  ellenőrizd:

    if (opStack[qIndex].parenDepth != parenDepth) {
        return fail("Nested ternary requires parentheses");
    }

Ez biztosítja:

-   ha a ? és : nem ugyanabban a zárójel-szintben vannak → hiba
-   vagyis a nested ternary csak zárójelezve engedélyezett

------------------------------------------------------------------------

⭐ 6. Optional true‑ágának ellenőrzése

A ? után nézd meg a következő tokent:

    Token next = tokens[i];

    bool nextIsSimple =
        next.type == TokenType::Variable ||
        next.type == TokenType::Number ||
        next.type == TokenType::StringLiteral;

    if (!nextIsSimple && next.type != TokenType::LParen) {
        return fail("Optional expression requires parentheses for complex expressions");
    }

Ez tiltja:

    flag ? a+b        // ❌ hiba
    flag ? x>10       // ❌ hiba
    flag ? cond ? A:B // ❌ hiba

És engedi:

    flag ? (a+b)      // ✔
    flag ? (cond ? A : B) // ✔

------------------------------------------------------------------------

⭐ 7. AST‑builderhez nem kell hozzányúlni

A RPN már helyes lesz → az AST automatikusan jó.
