2️⃣ PATCH 5 – BarcodeRegistry ledger‑tesztek

Fájlok: tests/barcode_registry_tester.cpp, tests/CMakeLists.txt

🎯 Cél (tömör összefoglaló)

Biztosítani, hogy a BarcodeRegistry ledger‑modellje:

-   helyesen kezeli az append‑only életút‑modellt,
-   helyesen kezeli a retiredAt mezőt,
-   helyesen enforce‑olja a ledger‑szintű invariánsokat,
-   helyesen működik Validator nélkül is (közvetlen ledger‑viselkedés),
-   helyesen importál CSV‑ből (repository → ledger‑record).

🧩 Mit kell tesztelni? (pontonként)

1.  InsertInternal – új rekord
    -   code nem üres
    -   introducedAt kitöltve
    -   retiredAt üres
2.  UpdateInternal – retire művelet
    -   retiredAt > introducedAt
    -   status = Retired
3.  Globális uniqueness (code + entityType)
    -   két azonos code + entityType → hiba
    -   eltérő entityType → engedélyezett
4.  CSV import → BarcodeRecord build
    -   barCode → code mapping
    -   retiredAt üres → Active
    -   retiredAt kitöltve → Retired
5.  Ledger invariánsok
    -   üres code → reject
    -   introducedAt invalid → reject
    -   retiredAt < introducedAt → reject
6.  EntityId mező
    -   CSV‑ben nincs → runtime trace mező üres
    -   ledger‑ben optional → nem kötelező

🛠️ Implementációs terv (pontonként)

1.  Hozd létre a barcode_registry_tester.cpp fájlt.
2.  Add hozzá a CMake‑hez.
3.  Írj 6 külön tesztcsoportot (fenti pontok szerint).
4.  Minden teszt legyen önálló, ne függjön Validator‑tól.
5.  Használj fix időpontokat (QDateTime::fromString).
6.  Minden teszt assertelje a ledger invariánsokat.

3️⃣ PATCH 6 – BarcodeGenerator tesztek

Fájl: tests/barcode_generator_tester.cpp

🎯 Cél (tömör összefoglaló)

Biztosítani, hogy a BarcodeGenerator:

-   determinisztikus,
-   nem generál ütköző kódot,
-   tiszteletben tartja a Validator szabályait,
-   helyesen működik üres ledger esetén,
-   helyesen működik nagy ledger esetén.

🧩 Mit kell tesztelni? (pontonként)

1.  Deterministic seed → deterministic output
2.  Generated code ≠ üres
3.  Generated code nem ütközik meglévő ledger‑rekorddal
4.  Tömeges generálás (1000 db) → nincs ütközés
5.  Validator integráció
    -   üres kód → tiltva
    -   ütköző kód → tiltva
6.  Edge case
    -   ledger tele van → fallback működik

🛠️ Implementációs terv (pontonként)

1.  Hozd létre a barcode_generator_tester.cpp fájlt.
2.  Add hozzá a CMake‑hez.
3.  Mockold a BarcodeRegistry‑t (vagy használj in‑memory példányt).
4.  Írj 6 tesztcsoportot (fenti pontok szerint).
5.  Használj fix seed‑et a determinisztikus tesztekhez.
6.  Asserteld, hogy a generált kód mindig megfelel a Validator
    szabályainak.

Zoltán, most már minden lényeges fájl a kezedben van, és látom, hogy
pontosan azt szeretnéd: a PATCH 5 és PATCH 6 tesztjeit úgy megtervezni,
hogy azok illeszkedjenek a projekted valódi teszt‑architektúrájához —
ami NEM QtTest, NEM GoogleTest, hanem egy saját, modul‑alapú,
smoke‑szerű unit‑teszt keretrendszer.

Ez a keretrendszer:

-   TestModuleBase → minden tesztmodul ebből származik
-   run() → a modul futtatása
-   fullResultString() → eredmény formázása
-   TestManager → modulok futtatása profil alapján
-   minden tesztmodul saját metódusokkal tesztel
-   a tesztek Q_ASSERT‑ot használnak
-   a tesztek nem izoláltak, hanem a registryk singletonjai miatt
    globális állapotot használnak
-   a tesztek clearForTest()‑tel törlik a registryket

Ez azt jelenti, hogy a PATCH 5 és PATCH 6 tesztjeit pontosan ilyen
formában kell megírni, nem pedig GoogleTest‑szerűen.

Most megtervezem neked a két tesztmodult pontosan ebben a formátumban, a
projekted stílusához igazítva.

✅ 2️⃣ PATCH 5 – BarcodeRegistry ledger‑tesztek (projekt‑kompatibilis formában)

📌 Tesztmodul neve

    test/barcode/barcode_registry_tester.cpp

📌 Osztály skeleton (a projekt stílusában)

    #pragma once
    #include "test/common/test_module_base.h"

    class BarcodeRegistryTester : public TestModuleBase {
    public:
        BarcodeRegistryTester()
            : TestModuleBase("BarcodeRegistry")
        {}

        bool run() override;

    private:
        void testRegisterNewUnique();
        void testRegisterCollisionDifferentEntity();
        void testRegisterSameEntityTwice();
        void testRetire();
        void testRetireThenRegisterAgain();
        void testEntityIdMissingNoCollision();
        void testCsvRoundtrip();
    };

📌 run() metódus (a projekt mintájára)

    bool BarcodeRegistryTester::run()
    {
        zInfo("=== BarcodeRegistry TESTS START ===");

        testRegisterNewUnique();
        testRegisterCollisionDifferentEntity();
        testRegisterSameEntityTwice();
        testRetire();
        testRetireThenRegisterAgain();
        testEntityIdMissingNoCollision();
        testCsvRoundtrip();

        zInfo("=== BarcodeRegistry TESTS END ===");
        return true;
    }

📌 Tesztmetódusok (rövid tervek)

1) testRegisterNewUnique()

-   registry.clearForTest()
-   registerNew(“ABC”, “Material”, id1, “Mat1”)
-   assert: findByCode(“ABC”) != nullptr
-   assert: isActive()

2) testRegisterCollisionDifferentEntity()

-   két külön id
-   ugyanaz a code
-   első succeed
-   második fail

3) testRegisterSameEntityTwice()

-   ugyanaz az id
-   második hívás → true, no‑op

4) testRetire()

-   registerNew
-   retire
-   assert retiredAt.has_value()

5) testRetireThenRegisterAgain()

-   registerNew
-   retire
-   új registerNew ugyanazzal az entityId‑val → új rekord? vagy update?
    → a jelenlegi kód szerint: nem engedi újra, csak update‑elné, de
    retired esetén új insert nincs → ezt explicit tesztelni kell

6) testEntityIdMissingNoCollision()

-   előre betöltött CSV‑ből rekord entityId nélkül
-   új registerNew ugyanazzal a code‑dal → succeed

7) testCsvRoundtrip()

-   registry.clearForTest()
-   insert 2 rekord
-   saveToCSV()
-   load() → QVector
-   assert: 2 rekord, mezők egyeznek
