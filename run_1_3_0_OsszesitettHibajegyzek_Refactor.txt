------------------------------------------------------------------------

1. Cél és scope – mit hoz PATCH 22?

Fókusz: belső workbench‑állapot mentése / visszaállítása, nem
UI‑geometria.

Konkrétan az OrderWorkbench esetén:

-   utolsó kiválasztott rendelés ID mentése
-   (később bővíthető) szűrő / kereső állapot mentése
-   mindez ini‑ben, a meglévő UI snapshot mellett, külön prefix alatt
-   restore eseményblokkolással, hogy ne „robotizáljuk” a workbenchet

A WorkbenchStateManager:

-   marad UI snapshot manager
-   kiegészül egy „custom state” réteggel (kulcs‑érték alapú, ini‑ben)

------------------------------------------------------------------------

2. Döntés: közös ini, külön prefix

-   Ugyanaz az ini, amit a WidgetStateManager és a WorkbenchStateManager
    már használ.

-   Külön namespace / prefix a custom state-nek, pl.:

    -   order_workbench/customState/selectedOrderId
    -   order_workbench/customState/filterCustomer
    -   stb.

Előnyök:

-   egy workbench = egy logikai namespace
-   snapshot + custom state nem keveredik, de együtt él
-   minimális diff, nincs új fájlformátum, nincs új storage‑réteg

------------------------------------------------------------------------

3. IWorkbenchCustomState interface – a szerződés

Új interface, amit bármely workbench implementálhat, ha custom state‑et
akar:

    class IWorkbenchCustomState {
    public:
        virtual ~IWorkbenchCustomState() = default;

        virtual QVariantMap saveCustomState() const = 0;
        virtual void restoreCustomState(const QVariantMap& state) = 0;
    };

Elv:

-   Workbench tudja, mit akar menteni (ID, filter, search, stb.)
-   Workbench tudja, hogyan kell visszaállítani
-   WorkbenchStateManager csak tárol, nem értelmez

        // ...
        QVariantMap loadCustomState(const QString& id);

    };

4.2. Implementáció (ini‑alapú, a meglévő settings infra fölött)

A WidgetStateSettings / SettingsStore / SettingsManager mintájára:

-   loadCustomState(id):
    -   beolvassa az id + "/customState/..." alatti kulcsokat
    -   QVariantMap-ként adja vissza
-   saveCustomState(id, state):
    -   kiírja az id + "/customState/..." alá a kulcsokat

Kulcsminta:

-   id + "/customState/selectedOrderId"
-   id + "/customState/filterCustomer"

5. WorkbenchStateManager – integráció a tab‑aktiválási ciklusba

5.1. onTabActivated – restore sorrend

Most:

-   csak WidgetStateManager(id).restoreWidgetState(wb);

Ezután:

    void WorkbenchStateManager::onTabActivated(QWidget* wb) {
        if (_closing)
            return;

        QString id = findIdByWidget(wb);
        if (id.isEmpty())
            return;

        auto& info = _workbenches[id];
        if (!info.wasShown) {
            WidgetStateManager c(id);
            c.restoreWidgetState(wb);

            // Custom state restore
            if (auto* cs = qobject_cast<IWorkbenchCustomState*>(wb)) {
                QVariantMap m = loadCustomState(id);
                cs->restoreCustomState(m);
            }

            info.wasShown = true;
        }
    }

5.2. onTabDeactivated – save sorrend

Most:

-   csak WidgetStateManager(id).saveWidgetState(wb);

Ezután:

    auto doSave = [id, wb]() {
        WidgetStateManager c(id);
        c.saveWidgetState(wb);

        if (auto* cs = qobject_cast<IWorkbenchCustomState*>(wb)) {
            QVariantMap m = cs->saveCustomState();
            saveCustomState(id, m);
        }
    };

6.2. saveCustomState – mit mentünk első körben?

MVP:

-   utolsó kiválasztott rendelés ID

    QVariantMap OrderWorkbench::saveCustomState() const
    {
        QVariantMap m;
        if (_listPanel) {
            QUuid id = _listPanel->selectedOrderId();
            if (!id.isNull())
                m["selectedOrderId"] = id.toString();
        }
        return m;
    }

6.3. restoreCustomState – biztonságos visszaállítás

    void OrderWorkbench::restoreCustomState(const QVariantMap& state)
    {
        if (!_listPanel)
            return;

        QSignalBlocker b1(_listPanel);

        const QString idStr = state.value("selectedOrderId").toString();
        if (idStr.isEmpty())
            return;

        QUuid id(idStr);
        if (id.isNull())
            return;

        _listPanel->selectById(id);
    }

Fontos:

-   csak ID‑t állítunk vissza
-   nincs Presenter hívás innen
-   a selectById() belsőleg válthat orderSelected signalt → ezt később
    finomíthatjuk (pl. külön „silentSelectById” API-val), de első körben
    elég, ha a QSignalBlocker a ListPanel szintjén blokkolja a
    jelzéseket.

8. Implementációs terv + files.txt

8.1. Lépésenkénti implementációs terv

1.  Komment WorkbenchStateManager elé
    – amit már megfogalmaztunk: tisztázza, hogy UI snapshot manager, nem
    belső state manager.

2.  IWorkbenchCustomState interface létrehozása

    -   új header: pl. common/ui_state/i_workbench_custom_state.h

3.  WorkbenchStateManager bővítése

    -   loadCustomState(id) + saveCustomState(id, state) privát
        metódusok
    -   onTabActivated + onTabDeactivated módosítása a custom state
        hívásokkal

4.  OrderWorkbench módosítása

    -   öröklődés IWorkbenchCustomState-ből
    -   saveCustomState() + restoreCustomState() implementálása
    -   (opcionális) a korábbi hideEvent-es WidgetStateManager hívások
        eltávolítása, ha még maradtak

5.  OrderHeaderListPanel API ellenőrzése / bővítése

    -   selectedOrderId()
    -   selectById(const QUuid&)

6.  Build + manuális teszt

    -   Order tab megnyit → kiválasztasz egy rendelést → kilépés →
        újraindítás → tab restore után ellenőrzöd, hogy ugyanaz az order
        van fókuszban.

7.  Későbbi bővítés (nem része most a patchnek, de előkészítve):

    -   filter mezők mentése (filterCustomer, filterStatus, stb.)
    -   keresőmező mentése
