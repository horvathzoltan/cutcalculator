Nagyon jó, hogy most megállsz—ilyenkor szoktak elszállni a parser‑refaktorok. Csináljunk egy **jó, másnapi‑fejjel‑olvasható** tervet.

---

### Kontextus snapshot (hol tartunk most)

**Jelenlegi állapot:**

- A `Parser::toRpn`:
  - kezeli:
    - literálok, változók
    - függvényhívás + `argc`
    - bináris operátorok precedenciával
    - `?` → csak push a stackre
    - `:` → kipucol bináris opokat a `?`‑ig, de nem zár
  - a végső drain‑ben:
    - `?` → `Choose` tokenné alakul
    - `Choose` / `Opt` nem kerül RPN‑be (prefix jelölőként voltak használva)
- A nested `choose` most ilyen RPN‑t ad:

  ```txt
  w 1500 > h 1500 > X Y Z choose choose
  ```

- Az AST‑builder ezt így értelmezi:

  ```txt
  Choose
    ├─ cond1: (w > 1500)
    ├─ cond2: (h > 1500)
    └─ Choose(X, Y, Z)
  ```

- Az `eval`‑ban volt/van egy speciális `Choose` ág, ami ezt a mintát kézzel értelmezi.
- A felismerés: **ez nem általános beágyazás**, hanem egy konkrét AST‑minta kézi kezelése.

**Cél holnapra / p11‑től:**

- A parser **általánosan** tudjon beágyazást:
  - bármilyen operátorral
  - bármilyen mélységben
  - choose/opt/függvény/assignment/stb. kombinációkban
- A ternary (`? :`) legyen:
  - rendes, right‑associative, 3‑operandusú operátor
  - prefix `choose:` csak „ráül” erre, nem külön hack

## „Általános beágyazást kezelő parser” – patch terv (p1…pN)

### p1 – Fogalmi tisztázás, invariánsok

**Cél:** legyen 3 kristálytiszta invariáns:

1. **Expression**: egy összefüggő kifejezés, amit RPN‑re fordítunk.
2. **Ternary**: `cond ? a : b` → mindig pontosan 3 operandus.
3. **Prefix blokk**: `choose: <expression>` → egy teljes expressionre vonatkozik.

**Teendő (csak komment / jegyzet):**

- A `parser.h` / `parser.cpp` tetejére rövid komment:
  - mit tekintünk expressionnek
  - hogyan kezeljük a ternaryt
  - hogyan kötjük a prefix `choose:`‑t egy expressionhöz

---

### p2 – Új struktúra: ExpressionContext

**Cél:** a parser tudja, mi történik egy adott expressionen belül.

**Teendő:**

- `parser.cpp`‑ben (fent, `toRpn` fölött) definiálni:

  ```cpp
  struct ExpressionContext {
      int openQuestions = 0;   // hány '?' van nyitva ebben az expressionben
      bool hasPrefixChoose = false; // volt-e 'choose:' az elején
  };
  ```

- `toRpn` elején:

  ```cpp
  QStack<ExpressionContext> exprStack;
  exprStack.push(ExpressionContext{}); // globális top-level expression
  ```

---

### p3 – `?` kezelése: ternary state

**Cél:** a `?` ne csak egy sima token legyen, hanem állapot is.

**Teendő:**

- A `Question` ágban:

  ```cpp
  if (t.type == TokenType::Question) {
      opStack.push(t);
      exprStack.top().openQuestions++;
      continue;
  }
  ```

- Ezzel jelezzük: ebben az expressionben van egy nyitott ternary.

---

### p4 – `:` kezelése: csak true‑ág vége

**Cél:** `:` ne zárja le a ternaryt, csak a true‑ágot.

**Teendő:**

- A `Colon` ág maradjon **nagyon egyszerű**:

  ```cpp
  if (t.type == TokenType::Colon) {
      while (!opStack.isEmpty() && opStack.top().type != TokenType::Question) {
          output.append(opStack.pop());
      }
      // A '?' a stacken marad, a ternary még nyitva.
      continue;
  }
  ```

- NINCS:
  - `?` pop
  - `Choose` generálás
  - prefix choose kezelés

---

### p5 – Prefix `choose:` mint expression‑nyitó

**Cél:** `choose:` ne operátor legyen, hanem expression‑scope jelölő.

**Teendő:**

- A `Choose` ágban:

  ```cpp
  if (t.type == TokenType::Choose) {
      // prefix choose: új expression context
      ExpressionContext ctx;
      ctx.hasPrefixChoose = true;
      exprStack.push(ctx);

      // a tényleges 'choose' tokent tegyük az opStack-re,
      // de csak jelölőként (nem kerül közvetlenül az RPN-be)
      opStack.push(t);
      continue;
  }
  ```

- Fontos: a prefix choose **nem kerül azonnal az outputba**.

---

### p6 – Expression boundary fogalma

**Cél:** definiálni, mikor ér véget egy expression.

**Expression vége lehet:**

- `RParen` (jobb zárójel)
- `Comma` (függvény argumentum vége)
- `End` (sor vége)
- top‑level `Newline` (nálad már van statementEnd)
- prefix `choose:` által nyitott expression lezárása (implicit, amikor a külső expression továbbmegy)

**Teendő:**

- Bevezetni egy segédfüggvényt (lokális lambda a `toRpn`‑ben):

  ```cpp
  auto closeExpression = [&](bool isFinal) {
      // 1) kipakoljuk a bináris operátorokat, amíg:
      //    - LParen
      //    - Function
      //    - Question
      //    - Choose (prefix jelölő)
      while (!opStack.isEmpty()) {
          Token top = opStack.top();
          if (top.type == TokenType::LParen ||
              top.type == TokenType::Function ||
              top.type == TokenType::Question ||
              top.type == TokenType::Choose)
              break;
          output.append(opStack.pop());
      }

      // 2) lezárjuk az összes nyitott '?' ebben az expressionben
      while (exprStack.top().openQuestions > 0) {
          // keresünk egy '?'‑t a stacken
          while (!opStack.isEmpty() && opStack.top().type != TokenType::Question) {
              output.append(opStack.pop());
          }
          if (opStack.isEmpty())
              break;

          opStack.pop(); // levesszük a '?'
          exprStack.top().openQuestions--;

          Token chooseTok;
          chooseTok.type = TokenType::Choose;
          chooseTok.text = "choose";
          output.append(chooseTok);
      }

      // 3) ha prefix choose volt ezen az expressionön → most kerül az RPN-be
      if (exprStack.top().hasPrefixChoose) {
          // a hozzá tartozó Choose token a stacken van
          while (!opStack.isEmpty() && opStack.top().type != TokenType::Choose) {
              output.append(opStack.pop());
          }
          if (!opStack.isEmpty() && opStack.top().type == TokenType::Choose) {
              Token ch = opStack.pop();
              ch.text = "choose"; // vagy "choose:" ha külön akarod jelölni
              output.append(ch);
          }
      }

      if (!isFinal)
          exprStack.pop();
  };
  ```

- A végső drain‑nél `closeExpression(true)` hívás.

---

### p7 – `RParen` integrálása az expression‑lezárásba

**Teendő:**

- A `RParen` ágban:

  1. kipakolni, amíg `LParen`
  2. `LParen` pop
  3. ha utána `Function` van → függvény lezárás (most is így van)
  4. **expression lezárás**:

  ```cpp
  if (t.type == TokenType::RParen) {
      while (!opStack.isEmpty() && opStack.top().type != TokenType::LParen) {
          output.append(opStack.pop());
      }
      if (!opStack.isEmpty() && opStack.top().type == TokenType::LParen)
          opStack.pop();

      // függvény lezárás (maradhat, ahogy most van)

      closeExpression(false);
      continue;
  }
  ```

---

### p8 – `Comma` integrálása expression‑lezárásba

**Teendő:**

- A `Comma` ágban:

  ```cpp
  if (t.type == TokenType::Comma) {
      closeExpression(false);
      if (!argCountStack.isEmpty())
          argCountStack.top()++;
      continue;
  }
  ```

- A függvény argumentumok így szépen külön expressionök lesznek.

---

### p9 – `End` / sorvége integrálása expression‑lezárásba

**Teendő:**

- A `End` / `Newline` kezelésnél:

  - a mostani „mindent kipakolunk” helyett:

  ```cpp
  if (t.type == TokenType::End) {
      break;
  }

  if (t.type == TokenType::Newline) {
      closeExpression(false);
      output.append({TokenType::StatementEnd, ";"});
      exprStack.push(ExpressionContext{}); // új top-level expression
      continue;
  }
  ```

- A végén, a `while (!opStack.isEmpty())` helyett:

  ```cpp
  closeExpression(true);
  ```

---

### p10 – Bináris operátorok: csak precedencia, semmi ternary‑logika

**Teendő:**

- A bináris operátor ág maradjon tisztán:

  ```cpp
  if (/* bináris op */) {
      while (!opStack.isEmpty()) {
          Token top = opStack.top();
          if (top.type == TokenType::LParen ||
              top.type == TokenType::Function ||
              top.type == TokenType::Question ||
              top.type == TokenType::Choose)
              break;

          if (precedence(top) < precedence(t))
              break;

          output.append(opStack.pop());
      }
      opStack.push(t);
      continue;
  }
  ```

- NINCS benne ternary lezárás.

---

### p11 – Takarítás: régi ternary‑hackek eltávolítása

**Teendő:**

- A végső drain‑ből:
  - kivenni a `Question`‑speciális ágat (mert most már `closeExpression` kezeli)
  - kivenni a `Choose` / `Opt` „ne kerüljön RPN‑be” hackeket (prefix choose már context‑szinten van kezelve)
