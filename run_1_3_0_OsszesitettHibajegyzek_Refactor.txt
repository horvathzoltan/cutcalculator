🎯 Mi volt a valódi probléma?

A kettős CRUD‑út eredeti célja:

-   UI → workflow (validáció + persist)
-   Business logic → gyors CRUD (nincs workflow)

Ez érthető volt, de két kritikus dolog kimaradt:

1.  A business‑logic által létrehozott entitás is adatbázis‑művelet,
    tehát perzisztálnia kell.
2.  A CSV betöltés nem mehet át a workflow‑n, mert akkor visszamentené a
    fájlt.

Ezért alakult ki a kettős út, de:

-   a „gyors CRUD” nem perzisztál,
-   a workflow perzisztál,
-   a betöltés workflow‑t kerül,
-   a business logic véletlenül a gyors CRUD‑ot használja,
-   a persist‑policy implicit és dokumentálatlan.

Ez vezetett a mátrix‑persist hibához.

------------------------------------------------------------------------

🟩 A helyes megoldás: 1 út + 1 kivétel

✔ Minden CRUD művelet workflow‑n keresztül menjen

Ez garantálja:

-   validáció
-   duplikáció‑ellenőrzés
-   domain hookok
-   logolás
-   persist()

✔ KIVÉTEL: CSV betöltés

A betöltés nem CRUD, hanem:

-   setAll()
-   workflow nélkül
-   persist nélkül
-   log nélkül

Ez a helyes modell.

------------------------------------------------------------------------

🟦 Miért nem gond workflow‑t használni minden CRUD‑ra?

-   gyors
-   biztonságos
-   auditálható
-   konzisztens
-   nem kerülhető meg
-   minden registry ugyanúgy működik
-   nincs implicit viselkedés
-   nincs runtime‑only adat
-   nincs elvesző adat

Ez a helyes architektúra.

------------------------------------------------------------------------

🟥 A CSV betöltés visszaperzisztálásának megoldása

A betöltés jelenleg:

-   repository.load() → QVector
-   registry.setAll()
-   onItemsChanged()
-   DE: ha a registry insert/update/remove workflow‑os, akkor a
    betöltéskor használt insert() visszamentené a CSV‑t.

Ezért kell:

✔ A betöltés NE használjon insert/update/remove‑ot

Hanem:

    registry.setAll(defs);
    registry.onLoadLog();

Ez már így működik a legtöbb registryben.

✔ A persist() NE fusson betöltéskor

A persist() csak workflow végén fusson.

✔ A betöltés legyen „transaction‑free”

Ez a jelenlegi architektúrával kompatibilis.

------------------------------------------------------------------------

🔧 PATCH 1 – A CrudMixin elrejtése

1. A CrudMixin insert/update/remove metódusait tedd protected‑dé

Így:

-   nem hívhatja business logic
-   nem hívhatja MatrixGenerator
-   nem hívhatja UI
-   csak a workflow mixin fér hozzá

Ez megszünteti a runtime‑only CRUD lehetőségét.

------------------------------------------------------------------------

🔧 PATCH 2 – A registryk publikus CRUD API‑ja workflow‑os legyen

Minden registryben:

    bool insert(const Entity& e) { return insertWithWorkflow(e); }
    bool update(const Entity& e) { return updateWithWorkflow(e); }
    bool remove(const IdType& id) { return removeWithWorkflow(id); }

Ez már sok helyen így van, de egységesíteni kell.

------------------------------------------------------------------------

🔧 PATCH 3 – Új API: insertInternal() csak betöltéshez

A RegistryEngineBase‑ben:

    bool insertInternal(const Entity& e) { return add(e); }

Ez:

-   nem workflow
-   nem persist
-   nem logol
-   nem validál
-   csak betöltéshez használható

------------------------------------------------------------------------

🔧 PATCH 4 – Repository load() → registry.setAll()

Minden repository betöltés után:

    registry.setAll(defs);
    registry.onLoadLog();

Ez már így működik, de egységesíteni kell.

------------------------------------------------------------------------

🔧 PATCH 5 – MatrixGenerator átállítása workflow‑ra

Ahol most:

    NeedCalculationDetailRegistry::instance().insert(detail);

Ott legyen:

    NeedCalculationDetailRegistry::instance().insert(detail);

Ez workflow‑os, persistáló út.

------------------------------------------------------------------------

🔧 PATCH 6 – Dokumentáció: registry_persist_model.md

Tartalmazza:

-   CRUD = workflow
-   insertInternal = betöltés
-   persist = workflow végén
-   betöltés = persist nélkül
-   nincs runtime‑only CRUD

------------------------------------------------------------------------

🔧 PATCH 7 – Unit tesztek

-   insert → persist() hívódik
-   update → persist() hívódik
-   remove → persist() hívódik
-   load → persist() NEM hívódik
-   MatrixGenerator → persist() hívódik
