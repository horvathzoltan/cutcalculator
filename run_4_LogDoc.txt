# 📘 **Feljegyzés a CutCalculator Logger‑architektúrához**
*(illeszthető a Handbook v1.0 „Logging Architecture” fejezetébe)*

## 🎯 **Bevezetés**

A CutCalculator log‑architektúrája három, egymástól élesen elkülönülő rétegre épül:

1. **DebugLog** – fejlesztői diagnosztika (TRACE, DEBUG)
2. **SystemLog** – technikai és domain audit (INFO, WARNING, ERROR)
3. **EventLog** – user‑szintű workflow események (INFO)

A Logger osztály mindhárom réteget kiszolgálja, de **eltérő célokkal, eltérő életciklussal és eltérő következményekkel**.

A rendszer stabilitása és auditálhatósága érdekében a három réteg **nem keverhető**, és minden loghívásnak egyértelműen beazonosítható szerepe van.

---

# 🧩 **1. DebugLog – fejlesztői diagnosztika (TRACE, DEBUG)**

A DebugLog kizárólag fejlesztői eszköz.
Nem része a rendszer működésének, nem auditálható, nem kerül be a végfelhasználói logokba.

### TRACE – „itt jár a kód”
- minimális információ
- stack trace nélkül
- stepping támogatás
- csak QT_DEBUG alatt aktív
- nem állítja meg a futást

### DEBUG – „mély hibakeresés”
- stack trace generálódik
- fejlesztői diagnosztika
- Linuxon `_isBreakOnError == true` esetén **megállítja a futást** (exit)
- Windowsra opcionálisan `__debugbreak()` tehető
- csak fejlesztés közben használjuk

**Szabály:**
TRACE/DEBUG csak akkor kerülhet be a kódba, ha a fejlesztőnek *nincs rálátása* a vezérlés útjára, vagy egy adott debug‑szituációban célzott diagnosztikai üzenetet akar elhelyezni.

---

# 🧩 **2. SystemLog – technikai és domain audit (INFO, WARNING, ERROR)**

A SystemLog a CutCalculator belső működésének auditálható rétege.
Minden domain művelet, repository/registry interakció és technikai állapotváltozás ide kerül.

### INFO – „normál működés”
- auditálható
- domain műveletek
- technikai műveletek
- snapshot restore
- registry insert/update/remove
- repository load/save

### WARNING – „hiba történt, de tovább tudunk menni”
- fallback
- részleges siker
- invalid input
- degradált működés
- a program folytatható

**Ökölszabály:**
> Ha a program tovább tud menni → WARNING.

### ERROR – „hiba történt, és nem tudunk tovább menni”
- kritikus hiba
- nincs fallback
- nincs default
- a rendszer működésképtelen
- stack trace generálódik
- exit() / abort()

**Ökölszabály:**
> Ha a program nem tud tovább menni → ERROR.

Példák ERROR-ra:
- osztás nullával
- beállításfájl nem nyitható meg
- repository nem írható
- sérült registry

---

# 🧩 **3. EventLog – user‑szintű workflow események (INFO)**

Az EventLog a felhasználó által kiváltott UI‑eseményeket rögzíti:

- dialógus megnyitása
- gombnyomás
- drag & drop
- BOMWorkbench megnyitása
- snapshot restore UI‑szinten
- user által indított műveletek

**Szabály:**
EventLog soha nem tartalmazhat WARNING vagy ERROR szintet.
A user‑szintű hibák UI‑visszajelzéssel kezelendők, nem logszinten.

---

# 🧩 **4. A három réteg közötti döntési fa**

```
Hiba történt?
    |
    ├── Nem → INFO (SystemLog vagy EventLog)
    |
    └── Igen →
           |
           ├── Tudunk tovább menni? → WARNING (SystemLog)
           |
           └── Nem tudunk → ERROR (SystemLog)
```

DebugLog nem része ennek a döntési fának — az külön fejlesztői eszköz.

---

# 🧩 **5. Logger API szereptérkép**

| Logger hívás | Szint | Réteg | Mikor használjuk |
|--------------|-------|--------|-------------------|
| `zTrace()` | TRACE | DebugLog | vezérléskövetés |
| `zDebug()` | DEBUG | DebugLog | mély hibakeresés |
| `zInfo()` | INFO | SystemLog | domain/technikai esemény |
| `zWarning()` | WARNING | SystemLog | nem kritikus hiba |
| `zError()` | ERROR | SystemLog | kritikus hiba |
| `zEventINFO()` | INFO | EventLog | user‑szintű esemény |

## 6.2. A meglévő dokumentumban cserélendő vagy pontosítandó részek
- mindenhol, ahol a logolás „egyszintűnek” van leírva → átírni háromszintűre
- a régi „AuditLog” kifejezést teljesen törölni
- a „verbose logging” részt átírni a Logger `_isVerbose` működésére
- a snapshot‑architektúra logolását átírni EventLog + SystemLog kettősre
- a Presenter/Manager logolási szabályokat frissíteni (UI → EventLog, domain → SystemLog)

## 6.3. Kódoldali változtatások (ha szükséges)
- minden UI‑szintű `zInfo()` → `zEventINFO()`
- minden domain‑szintű `zEventINFO()` → `zInfo()`
- minden nem kritikus hiba `zError()` → `zWarning()`
- minden kritikus hiba `zWarning()` → `zError()`
- TRACE/DEBUG csak fejlesztői célra maradjon
